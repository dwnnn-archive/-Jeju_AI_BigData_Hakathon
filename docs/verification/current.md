## 재현하고 수정한 중요한 문제

1. 계산 잠금을 기다리던 승인이 만료 이후 실행되는 문제: 계산 잠금을 짧게 기다리고 확보 후 검증. SQLite 쓰기 잠금 획득 후에도 만료를 재검사한다. 실제 쓰기 잠금을 유지한 재현에서 만료 승인은 거절되고 의도·감사 기록 모두 생성되지 않았다.
2. 결정 직후 프로세스 중단 시 미결정으로 보이는 문제: 결정 의도와 `decision_pending`을 원자 저장하고 체크포인트와 대조해 복구한다. 일반 Exception 처리 없이 종료되는 경로도 검증했다.
3. 탭 복귀 중 중복 GET과 오래된 응답 덮어쓰기: 조회 직렬화, 가시성 세대, 분석 ID·버전·관측 시각을 검사한다.
4. 검토 창을 연 뒤 결과가 바뀌어도 동의가 유지되는 문제: 검토 시작 시 ID·토큰을 고정하고 대상 변경 시 제출을 차단한다.
5. 일시적인 DB 오류로 유일한 작업자가 종료되는 문제: 오류 기록, 재시도 및 `/ready` 제공.
6. 계산 완료 결과의 저장 실패를 `failed`로 잘못 확정하는 문제: 계산과 스냅샷 저장의 예외 경로를 분리하고 체크포인트에서 결과를 복구한다.
7. 만료를 통신 불명으로 분류해 재분석이 막히는 문제: `reviewExpired`와 통신 확인 상태를 분리한다. 승인만 잠그고 새 분석은 허용한다.
8. 접근성·표시 문제: 청록/보조 글자 대비, 모바일 시간 레이블 줄바꿈, 모달 포커스 복원을 보완했다. 이력 조회 전·조회 실패를 ‘기록 없음’으로 표시하지 않는다.

독립 읽기 전용 코드 리뷰에서 위 문제들을 재현했고, 수정 후 기존 문제 확인 범위에서 남은 중요한 문제 없음으로 확인받았다.

## PR #2 백엔드 CI 실패 수정

실패 단계는 `uv run --no-sync pytest -q`, 실패 테스트는 `test_concurrent_approvals_are_serialized`였다. 동시 승인 요청의 응답이 `[503, 200]`인데 테스트는 항상 `[200, 200]`을 기대했다.

서버는 계산 잠금을 최대 250ms만 기다리고 사용 중이면 503을 반환하는 계약이다. 느린 실행 환경에서는 정상적으로 발생할 수 있다. 기존 테스트에 승인 지연을 주입해 동일한 실패를 재현했다.

수정 후에는 동시 요청 중 503을 받은 요청을 **동일한 분석 ID·결과 토큰·결정 내용**으로 재시도한다. 최종 승인, 같은 알림 ID, 발송 시도 1회, 감사 기록 1건을 확인한다. 별도 테스트는 Event로 첫 승인을 붙잡아 503 경로를 확정적으로 만든다. 처리 중에는 `decision_pending`, 승인 불가, 알림·감사 기록 없음도 검사한다. 고정 sleep이나 CI 실행 속도에 의존하지 않는다.

수정 후 CI와 동일한 의존성 설치·Ruff 검사·형식 검사·전체 pytest 명령을 통과했다(64개). 동시 승인 관련 테스트 2개를 10회 반복 실행해 20개 사례 모두 통과했다.

변경 파일은 `backend/tests/test_api.py`와 이 검증 문서다. 검사 기준은 승인 API 계약 및 중복 부작용 방지다. 서버의 잠금·인증·만료 검증 정책은 그대로 적용된다. 원격 CI 성공 여부는 GitHub에서 별도로 확인해야 한다.

## 성능 측정

| 대상 | 표본 | 중앙값 | 95백분위 | 최대 |
|---|---:|---:|---:|---:|
| 계산 잠금을 보유한 작업자와 동시에 상태 HTTP 조회 | 100회 | 3.82ms | 9.85ms | 17.50ms |
| 결과가 로드된 상태에서 세 메뉴 전환 | 30회 | 17.10ms | 41.70ms | 54.70ms |

서버는 로컬 FastAPI TestClient이므로 실제 네트워크 왕복 시간을 포함하지 않는다. 메뉴는 Vite 개발 서버와 헤드리스 Chromium에서 DOM 클릭부터 제목 갱신 후 다음 프레임까지 측정했으며 물리적 입력 지연·실제 디스플레이 표시 시점은 포함하지 않는다. 부하·저사양 기기·배포 네트워크를 포괄하는 SLA나 ‘항상 100ms 이내’ 보장이 아니다. 분석 계산 시간과 모델 정확도를 측정한 수치도 아니다.

재현 스크립트:

```bash
# backend/에서
uv run python -m scripts.measure_status_latency
# frontend/에서 — 양쪽 개발 서버 실행 후
node scripts/measure-navigation.mjs
```

원본: [상태 조회](status-latency.json), [화면 전환](navigation-latency.json).

차트 코드는 결과가 생긴 뒤 별도 로드한다. 빌드 결과 초기 JS는 약 110kB gzip, 별도 차트 JS는 약 113kB gzip이다. CSS와 글꼴은 별도이며 한국어 글꼴은 unicode-range에 필요한 조각만 요청한다. 탭이 숨겨지면 폴링을 멈추고, 보이는 동안에도 직전 요청 완료 후 다음 요청을 예약한다.

## 남은 범위

전날 관측 기반 다음날 회귀 예측, 현장 데이터 품질/최신성, 모델 현장 오차, 실제 자원 가용량, 전력 설비 제어, 다중 호스트 큐는 검증·구현되지 않았다. 현재 구성은 단일 호스트에서 상태 표시와 검토 절차를 확인하기 위한 개발용 구성이다. CI 설정은 저장소에 추가했으며 로컬 검사와 원격 CI 결과는 구분한다.
