# 확인된 상태만 표시하는 실행 계약

사용자 승인 범위: 현재 백엔드를 학습하기 쉬운 구조로 정리하고, 빠른 탐색과 정확한 업무 상태를 구분한 프론트엔드를 구현한다. 모델의 예측 정확도 개선이나 실제 설비 제어는 이번 변경의 범위가 아니다.

## 구성과 선택

React/TypeScript/Vite 프론트엔드와 FastAPI/LangGraph 백엔드를 분리한다. 기존 동기 분석 엔진 위에 SQLite 영속 작업 큐를 둔다. 별도 Redis/Celery 서비스는 단일 호스트 시연에 비해 운영 부담이 크므로 현재는 프로세스 간 리더 잠금을 가진 작업 스레드 하나를 사용한다. 상태 조회는 계산 엔진 잠금을 사용하지 않고 짧은 DB 읽기로 처리한다.

## 상태의 근거

- 전송 중: 브라우저가 HTTP 요청을 시작한 상태. 서버 실행을 뜻하지 않는다.
- queued: 서버 DB에 작업이 저장됐다. POST는 202와 분석 ID를 반환한다.
- running: 작업자가 계산 잠금을 획득하고 실행을 시작했다. 시작 시각과 생존 신호를 기록한다.
- status_unknown: 작업자의 생존 신호가 만료되었거나 클라이언트가 최신 응답을 확인하지 못한다. 실패/실행 중으로 추정하지 않는다.
- awaiting_approval/completed: 저장된 결과를 검증한 후 공개한다. 실제 현장 정확도 검증을 뜻하지 않는다.
- failed: 서버가 실행 예외를 확인하고 기록한 상태.
- approved/rejected: 정확한 결과 토큰에 대해 인증된 결정이 저장됐다.

Idempotency-Key(UUID)는 분석 ID와 같다. 같은 키/같은 입력은 같은 작업을 반환하고, 다른 입력은 409다. 브라우저는 접수 응답이 유실되면 같은 키로 상태를 조회하거나 같은 요청만 재전송한다. 새로운 분석 버튼으로 중복 생성하지 않는다.

## 승인 조건

결과 토큰은 분석 ID·요청·결과·출처·배분안·초안의 SHA-256이다. 요청은 result_token과 승인/반려 사유를 포함한다. 서버는 최신 분석 여부, 유효기간, 상태, 토큰, 데이터 적합성을 다시 검사한다. 같은 날짜/지역/모드의 새 분석이 접수되면 이전 결과의 신규 승인 권한을 철회한다. 시연 모드의 승인은 모의 알림만 허용한다. live의 미검증 모델/가용량은 승인 및 외부 발송을 차단한다. 위험 미해결 경계도 승인 차단한다. 기본 결과 검토 유효기간은 완료 후 60분이다(운영 도입 시 업무 정책 검토 필요).

live에서 Mock 폴백은 기본 비허용이다. 데이터가 없으면 실패 사실을 표시한다. 현재 실 데이터 최신성/모델 현장 정확도는 검증되지 않았으므로 live 결과는 참고용이며 운영 조치를 허용하지 않는다.

## 장애 복구

작업자 리더가 바뀌면 중단된 running은 interrupted로 기록한다. 완료됐지만 작업 메타데이터 반영 전에 중단된 경우 저장된 그래프의 최종 상태를 대조해 복구한다. 승인 의도는 그래프 재개 전에 저장해 충돌하는 재시도를 거부한다. 알림 상태는 별도로 조회하고, 발송 성공을 설비 동작 성공으로 표현하지 않는다.

## 화면 원칙

화면 전환은 즉시, 일반 색상 피드백은 80ms, 보조 패널은 최대 120ms. 업무 상태에는 낙관적 업데이트를 사용하지 않는다. 입력 날짜/지역과 결과의 날짜/지역을 함께 표시한다. 결과가 없으면 차트를 비우고 안내한다. 오류 시 이전 결과를 숨기거나 과거 결과로 표시하며 승인 버튼을 잠근다. 키와 승인 토큰은 브라우저 메모리에만 둔다. 스크롤/포커스/모달은 접근성을 유지한다.

## 검토 중단과 만료의 구분

새 결정의 의도와 `decision_pending` 공개 상태는 같은 SQLite 트랜잭션에서 저장한다. 그래프/감사 기록과 화면 스냅샷 사이에 프로세스가 종료되어도 복구 대상이 남는다. SQLite 쓰기 잠금을 얻는 데 시간이 걸릴 수 있으므로 트랜잭션을 획득한 다음에도 유효시간을 검사한다. 일시적인 결과 저장 오류는 계산 실패로 확정하지 않고 체크포인트 복구로 넘긴다.

브라우저에서는 `transport`(확인 가능 여부)와 `reviewExpired`(검토 유효시간)를 구분한다. 서버가 만료 상태를 확인해주면 새 분석은 시작할 수 있고 기존 결과의 승인만 차단한다. 7초 확인 유효시간과 검토 만료 타이머는 서버 관측 시각 및 응답 왕복 시간을 기준으로 계산한다. 동일 버전의 오래된 관측도 거부한다. 계산/접수/승인 성공에는 낙관적 업데이트를 적용하지 않는다.
