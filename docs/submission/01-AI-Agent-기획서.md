## 요약

**"내일 제주에서 전기가 남아 발전소를 강제로 멈추는 일(출력제한)이 생길지 미리 알려 주고, 남는 전기를 어디로 얼마나 보낼 수 있는지 대응 후보를 제안하는 Agent."**

## 1. 구현 목표 (분석 주제의 타당성과 창의성)

### 1.1 문제
제주는 풍력·태양광이 많아 수요가 적은 봄·가을 낮에 발전량이 수요를 넘습니다. 이때 계통 안정을 위해 발전기를 강제로 줄입니다. 제주 풍력은 2021-01 ~ 2024-05에 **335일, 1,567시간, 73,224 MWh**가 줄었습니다([실측], KPX 출력제어 이력). 버려지는 전기를 줄이려면 **하루 전에 위험을 알고 저장·소비처를 준비**해야 합니다.

### 1.2 이 서비스가 하는 일

| 목표 | 설명 |
|---|---|
| 하루 전 위험 판정 | 기상예보 → 제주 풍력·태양광 발전량 예측, 수요 예측 → **발전량 ÷ 수요 비율**로 정상·주의·위험 산정 |
| 당일 재점검 | 하루 전에 "정상"이던 날을 초단기예보로 다시 점검해 놓침을 줄임 |
| 자원 배분(대응 후보 제안) | 위험 시 피크 1시간의 남는 전력을 대형 ESS → 분산형 ESS → 수소 → 전기차 충전(EV) 순으로 얼마씩 보낼지 제안, 받지 못하는 **잔여 전력도 숨기지 않고 표시** |
| 사람이 결정 | 통보문 초안은 Agent가 쓰고, 문구 확인과 **발송은 도청 담당자가 확정한 뒤에만** 진행(시연은 모의 발송). Agent는 제어 명령을 내리지 않음 |

### 1.3 사용자와 역할의 경계
**제주특별자치도청 에너지 담당 부서의 담당자**(IT 비전문가)가 주 사용자이고, Agent는 이 담당자를 돕는 **보조 도우미**입니다. Agent가 위험을 알리고 통보문 **초안을 만들어 두면**, 담당자가 문구를 확인하고 **발송 여부를 정합니다**. 도청의 역할은 **조기 인지 → 대응안 검토 → 통보문 확인·발송 → 관계기관 통보**까지이고, **출력제한의 판단과 지시는 KPX의 역할**입니다. 그래서 Agent의 위험 등급은 도청이 쓰는 조기 인지용 참고 정보이며, 설비를 직접 제어하지 않습니다.

| 역할 | 누구 | 비고 |
|---|---|---|
| 예상 사용자(시연 페르소나, 주 사용자) | **도청 에너지 담당 부서 담당자** | 상황 인지, 통보문 확인·발송 결정, 충전소·사업자 협조 요청 초안 확인 |
| 정보 공유·확장 경로 | 계통 운영 기관(KPX, 한전 등) | 확장 시 실시간 데이터 연동 |
| 수혜자 | 전기차 이용자, 충전소 운영자, 재생에너지 사업자 | 사전 정보 |
| 귀속 | 제주빅데이터센터 | 산출물 귀속 |

위 사용자는 **예상 사용자(시연 페르소나)**입니다. 실제 도청 담당자의 사용성 확인은 5.3의 시범 운영 계획에 두었습니다.

### 1.4 차별점
- **데이터가 결과를 바꿉니다.** 충전기 출력·이용률을 가정하지 않고 허브 충전 이력으로 실측해 EV 용량을 계산합니다.
- **한계를 숫자로 보여 줍니다.** 같은 과거 날짜에 용량 기준만 바꿔 "공개된 제주 설비 규모(EV는 고정 40 MWh로 볼 때)로는 위험으로 판정한 날의 약 16.5%에서 잉여를 다 받지 못한다"는 결과를 냅니다. 이는 ESS·수소 확충이 필요하다는 근거로 읽을 수 있습니다.
- **LLM은 문장과 도구 선택을 맡고, 수치는 코드가 정합니다.** 통보문 문장을 쓰고, 담당자의 질문에는 읽기 전용 도구 6개 중 필요한 것을 골라 조회한 값으로 답합니다. 답의 숫자가 조회 결과에 없으면 쓰이지 않습니다.

## 2. 필수 데이터 활용 (제주데이터허브)

허브 데이터 4종을 **판단 경로와 검증 경로**에 실제로 사용했습니다. 활용 데이터 전체 목록과 이용 조건은 별첨 「데이터 활용 명세」에 있습니다.

| 허브 데이터 | 처리 방법 | 결과 |
|---|---|---|
| **전기자동차 충전소 정보 (No.494)** | API로 3,446행 수집 → 충전 방식별 중복 제거 **3,180곳**. 운영 시간 표기 정규화, 입주민·직원 전용 제외, 시간대별 운영 충전기 집계 | 12시 운영 충전소 2,969곳, 완속 6,005기·급속 2,462기로 **EV 용량과 충전소 TOP 5** 계산 |
| **전기자동차 충전 이력 (월별·요일별·일별)** | 2021-04, 2022-04 약 3.1만 건. 평균 전력 = 충전량÷충전 시간, 시간대별 점유율 = 충전 중인 시간÷가용 시간, 요일 보정 | 완속 **6.0 kW**, 급속 **36.7 kW**, 낮 12시 점유율 15.8%·12.1%. **EV 용량 82.6 → 109.0 MWh** |
| **일별 기상 정보 (No.756)** · **기상관측소 정보 (No.757)** | 날짜별 수집, 해발 100 m 미만 17곳 평균 기온, 편향 보정 | 기상청 ASOS와 상관 **0.996**, 편향 −0.5℃, MAE 0.7℃ (454일) |

**데이터 품질 사례**
- 충전기 번호(`evChargerId`)는 충전소마다 1번부터 다시 시작해, 이것만으로 세면 충전기가 25기로 잘못 계산되어 점유율이 100%로 나왔습니다. **(충전소, 충전기) 쌍으로 구분**하도록 고쳐 실제 742~841기를 얻었고 회귀 테스트를 추가했습니다.
- 충전소 운영 시간이 가이드(`00:00`)와 달리 `0:00`, `24:00:00`으로 내려와 정규화했고, 충전 방식별로 같은 충전소가 여러 행으로 내려와 266행을 합쳤습니다(합치지 않으면 충전기 수가 약 8% 부풀려집니다).
- 허브 일별 기상은 2025-03 말 이후 응답이 비어 있어 **서비스 입력이 아니라 교차검증에만** 썼습니다. 일별 충전 이력은 시간·요일 정보가 없어 점유율에는 쓰지 않고, **월별 합계와 일치하는지**(충전량 −0.00%, 횟수 +0.00%)와 날짜별 변동·이용 증가를 확인하는 데 썼습니다.
- 허브 API의 **일일 호출 한도**를 고려해 받은 달을 저장하고, 호출 횟수를 로그로 남기며, 한 번에 받을 달 수를 제한했습니다(재실행해도 같은 달을 다시 호출하지 않음).

## 3. Agent 개발 구성 (AI Agent 기술성과 완성도)

### 3.1 구조
Agent는 **도구 6개를 LangGraph 상태 그래프로 엮어** 판단하고, 사람의 승인을 받아 마무리합니다. 계산은 코드와 모델이, 문장과 질문 응대(도구 선택)는 LLM이, 결정은 사람이 맡습니다.

<!--FIG:arch-->

### 3.2 Workflow (LangGraph)

<!--FIG:flow-->

| 노드 | 하는 일 |
|---|---|
| weather | 기상청 단기예보에서 제주 풍속·기온·하늘상태 수집 |
| prediction | 제주 전체 풍력·태양광 발전량 예측 |
| demand | 제주 시간별 수요 예측(KPX 하루 전 수요예측이 있으면 우선) |
| risk | 발전량/수요 비율로 등급 결정, 비율 0.43~0.45이면 1회 재조회 |
| intraday_check | 초단기예보·실황으로 당일 재판정(최대 2회) |
| allocate | 피크 1시간 잉여를 자원별로 배분, **EV 용량은 허브 충전소·이력으로 계산** |
| draft / approval | 통보문 초안 작성, **담당자 승인 대기(중단 후 재개)** |

### 3.3 모델, 도구, LLM

| 구분 | 내용 |
|---|---|
| 발전량 모델 | 제주 전체 풍력·태양광 회귀(XGBoost). 풍력 정답은 출력제한 이력을 더해 **"제한이 없었다면의 발전량"**으로 보정 |
| 수요 모델 | 제주 시간별 수요 회귀. KPX 하루 전 수요예측과 비교 검증 |
| 위험 규칙 | 발전량/수요 비율 주의 0.40, 위험 0.45. 2021~2024 출력제한 이력으로 보정(이전의 잉여 150/200 MWh 규칙은 한 번도 못 잡아 교체) |
| 배분 용량 | BESS 37.7 MWh(제주 ESS 계량 실적의 시간당 최대 충전량 [실측]) · VPP 30(시연 추정) · P2X 3.3(행원 그린수소 실증단지 3.3 MW [보도]) · EV 109.0(허브 데이터) |
| LLM 1: 통보문 | **통보문 문장 작성(Claude, 선택)**. 확정 수치만 전달하고, 숫자가 입력과 다르거나 핵심 값이 빠지면 한 번 더 받고, 그래도 실패하거나 키가 없거나 호출이 실패하면 **템플릿 초안**으로 대체합니다. 이 경로에는 허브 원본과 충전소 이름을 보내지 않습니다. |
| LLM 2: 질문 응답 | **담당자의 질문에 Claude가 도구를 골라 답합니다(선택)**. 도구는 위험 판정, 시간별 예측, 자원 배분, 충전소, 데이터 출처, 검토 상태 조회의 **읽기 전용 6개**이고 승인·발송·설비 제어 도구는 없습니다. 도구는 숫자를 문자열로 만들어 돌려주고, 답의 숫자가 조회 결과나 질문에 없으면 한 번 더 받은 뒤 **기본(키워드) 답변**으로 대체합니다. 키가 없거나 호출이 실패해도 마찬가지입니다. 화면은 "AI 답변"과 "기본 답변"을 구분하고 조회한 도구를 보여 줍니다. 충전소 질문에는 충전소 이름·충전기 수·여력(공개 데이터)이 도구 결과로 전달됩니다. |

### 3.5 안정적 수행
- 작업은 SQLite 체크포인트에 저장되어 **서버가 재시작돼도 이어지고**, 승인은 결과와 묶여 결과가 바뀌면 이전 승인이 막힙니다.
- 응답이 사라져도 실패로 단정하지 않고 **상태 확인 불가**로 표시하며, 재요청은 같은 ID로 중복 작업을 막습니다.
- live 결과는 모델과 가용량이 운영 환경에서 검증되지 않았으므로(과거 자료 검증은 마쳤습니다) **승인과 실제 발송을 차단**합니다. 외부 조회가 실패해도 시연 값으로 몰래 바꾸지 않고 실패를 표시합니다.
- 테스트 **백엔드 235개, 화면 26개, 브라우저 종단 8개**. 외부 네트워크 없이 실행되며 복구·동시 승인·중복 방지·LLM 폴백을 포함합니다.

## 4. 편의성과 실용성

### 4.1 사용 흐름
설치 없이 브라우저로 사용합니다. **날짜 선택 → 분석 요청 → 결과 확인 → 승인**의 4단계입니다.

<!--FIG:flow4-->

- **당일 점검 버튼**: 하루 전 판정이 정상인 오늘 날짜의 결과가 확인되면 "당일 점검 요청" 버튼이 나타나 같은 조건으로 1차, 2차 점검을 요청합니다(하루 최대 2회, 서버가 규칙을 강제). 시연 조건 "당일 위험 전환"을 고르면 하루 전 정상 → 1차 정상 → 2차 위험 → 승인 대기까지 한 화면에서 따라갈 수 있습니다.
- **하루 업무 흐름**: 발전량 예측 화면 맨 위에 담당자의 하루 단계(전날 17:30 분석 → 07:45·10:45 점검 → 검토·승인 → 통보 → 09~15시 피크)를 보여 주고, 지금 보는 분석이 어느 단계인지 표시합니다. 단계 표시는 화면의 위치일 뿐 다른 날의 진행을 뜻하지 않습니다.
- 화면은 서버가 확인한 사실만 표시하고, **시연·가정 데이터에는 라벨**을 붙입니다(예: "허브 충전소 2,969곳 운영 중 · 충전 이력(2021~2022) 기반 이용률"). 배분 카드에는 자원별 근거 표시(BESS 자료 기반, P2X 보도 기준, **VPP 가정값 · 근거 자료 없음**)를 달아 어느 숫자를 믿고 어느 숫자를 확인해야 하는지 구분합니다.
- 위험일에는 **충전 여력이 큰 충전소 TOP 5**(충전기 수, 여력, 좌표)를 함께 보여 줍니다. 순위는 설치 규모 기준이며 충전소별 혼잡도는 반영하지 못한다고 화면에 적었습니다.
- 접근성: 자동 검사(axe)에서 검사한 데스크톱 결과·승인 창·모바일 승인 화면의 위반이 0건이었고, 키보드(Esc로 닫기, 포커스 복원)와 390px 모바일을 확인했습니다. 전체 WCAG 적합성 인증은 아닙니다.

### 5.2 한계 (숨기지 않고 밝힙니다)
1. **날씨는 실측을 예보 자리에 넣어** 점검했습니다(과거 예보 이력 없음). 예보 오차를 [시뮬레이션]으로 섞으면 정밀도가 76.7% → 49~63%로 떨어집니다.
2. **당일 점검의 효과(포착 81~83% → 약 93%)는 [시뮬레이션]**이며 실측 상승이 아닙니다.
3. 제주 출력제한 이력은 **2024-06 초에 끝납니다.**
4. **충전 이력은 2021-04, 2022-04의 과거 자료**입니다. 이후 전기차가 늘었다면 EV 용량(109.0 MWh)은 낙관적일 수 있고, 이력의 충전소는 허브 3,180곳의 일부입니다. 일별 이력에서 하루 평균 충전량이 1년 만에 **27% 늘었으므로**, 점유율을 2~3배로 키워도 EV 용량은 75~92 MWh, 위험일 흡수율은 63~71%임을 계산해 두었습니다(별첨 명세서 1.3절).
5. **BESS는 실적 기반 하한**이고, **P2X 3.3 MWh는 [보도]** 수치(공식 통계 아님), **VPP 30 MWh는 근거를 찾지 못한 시연 추정**입니다.
6. 이 서비스의 배분은 **참고용 대응 후보 제안**입니다. 도청이 배분을 정하는 것이 아니며, 설비 상태를 확인한 제어안도 아닙니다.
7. **LLM이 지휘하는 범위는 질문 응답과 문장 작성입니다.** 분석 파이프라인의 순서와 분기는 고정된 그래프이고, 재현성과 복구를 위해 의도한 설계입니다. 질문 응답의 정확도는 대표 질문을 실제로 돌려 확인한 수준이며 통계적으로 검증하지 않았습니다.

### 5.3 검증 현황과 시범 운영 계획

|---|---|---|---|
| 판정 정확도(실제 예보) | 과거 494일 실측 대조 [실측], 예보 오차는 [시뮬레이션] | 매일 자동 저장되는 예보·판정 이력으로 포착률과 오경보 재측정 | 포착률·정밀도가 5.1의 80.8%·76.7% 수준 유지 |

### 5.4 재현 방법
별첨 「매뉴얼」의 절차대로 **키 없이 시연 모드**를 바로 실행할 수 있고, `uv run pytest -q`와 `npm test`로 테스트를, `python -m scripts.allocation_sensitivity`로 배분 용량 통계를, `python -m scripts.evaluate_pipeline`으로 5.1의 판정 결과를 다시 만들 수 있습니다. 허브·KPX·기상청 원자료는 저장소에 넣지 않으며 받는 방법과 형식은 `docs/guides/data-acquisition.md`에 정리했습니다. GPU는 필요 없습니다.

## 6. 기술 환경과 기대 효과

- **환경**: Python 3.11+, FastAPI, LangGraph, SQLite / React, TypeScript, Vite. CPU만으로 센터 최소 사양(i7-8700 / GTX 1060 / RAM 32GB)에서 실행됩니다.
- **외부 서비스**: 기상청 API, 제주데이터허브 API, (선택) Claude API. 키가 없으면 시연 모드로 동작하고 화면에 표시합니다.
- **기대 효과**: 하루 전 위험 인지로 저장·소비처 준비 시간을 확보하고, 설비 규모의 부족분(잔여 전력)을 근거로 ESS·수소 확충 논의에 데이터를 제공합니다.
- **확장**: 예보 이력 기반 임계값 재보정, 읍면동별 흡수 여력 지도, 충전소별 우선순위, 실시간 충전기·ESS 상태 연동.
