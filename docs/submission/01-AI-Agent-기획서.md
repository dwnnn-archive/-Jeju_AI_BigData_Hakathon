# 제주 출력제한 대응 AI Agent 기획서

> 제주 AI·빅데이터 활용 AI Agent 개발 챌린지 제출용 (15쪽 이내)
> 팀명: **[팀명 입력]** · 작성일: 2026-11-17
> 표기 규칙: **[실측]** 은 실제 이력과 비교해 측정한 값, **[가정]** 은 자료가 없어 가정한 값, **[시뮬레이션]** 은 오차를 가정해 돌려 본 값입니다.

## 1. 구현 목표

### 1.1 분석 주제
**"내일 제주에서 전기가 남아 발전소를 강제로 멈추는 일(출력제한)이 생길지 미리 알고, 남는 전기를 어디에 보낼지 권고하는 Agent."**

제주는 풍력·태양광이 많아 수요가 적은 봄·가을 낮에 발전량이 수요를 넘습니다. 이때 계통 안정을 위해 발전기를 강제로 줄이는데, 제주 풍력의 경우 2021-01 ~ 2024-05에 **335일, 총 1,567시간, 73,224 MWh**가 줄었습니다 (KPX 출력제어 이력, **[실측]**). 버려지는 전기를 줄이려면 하루 전에 위험을 알고 저장·소비처를 준비해야 합니다.

### 1.2 AI를 활용한 데이터 분석 목표
| 목표 | 설명 |
|---|---|
| 하루 전 위험 판정 | 기상예보 → 제주 풍력·태양광 발전량 예측, 수요 예측 → **발전량 ÷ 수요 비율**로 위험 등급(정상·주의·위험) 산정 |
| 당일 재점검 | 하루 전에 "정상"이던 날을 당일 초단기예보로 다시 점검해 **놓침을 줄임** |
| 자원 배분 권고 | 위험 시 피크 1시간의 남는 전력을 대형 ESS → 분산형 ESS → 수소 → **전기차 충전(EV)** 순으로 얼마씩 보낼지 제안 |
| 사람이 결정 | 알림 발송은 **도청 담당자 승인 후에만** 진행. Agent는 제어 명령을 내리지 않으며, **출력제한의 판단과 지시는 KPX의 몫**이라 Agent의 위험 등급은 도청이 쓰는 조기 인지용 참고 정보임 |

### 1.3 이 서비스가 필요한 사람
**제주특별자치도청 에너지 담당 부서의 행정담당자**(IT 비전문가)가 "내일 위험한가, 얼마나, 어디로 보낼까"를 화면 한 곳에서 확인합니다.

도청의 역할은 **조기 인지 → 대응안 검토 → 승인 → 관계기관 통보**까지입니다. 출력제한을 판단하고 지시하는 것은 KPX의 역할이며, 이 서비스는 그 영역에 들어가지 않습니다. 설비를 직접 제어하지도 않습니다.

## 2. 서비스 제안

### 2.1 데이터 활용 개요
- **제주데이터허브 「전기자동차 충전소 정보」(No.494)** 를 배분 권고의 **EV 흡수 용량**에 사용합니다. 허브 API로 제주 충전소 **3,180곳**(원본 3,446행에서 중복 제거)을 수집해, 시간대별로 운영 중인 충전기 수를 계산합니다.
- 발전량·수요·출력제한 이력(KPX)과 기상 자료(기상청)는 위험 판정 모델의 학습·입력으로 씁니다. 상세는 별첨 「데이터 활용 명세」.

### 2.2 핵심 기능
1. **하루 전 분석**: 날짜를 고르면 시간별 발전량·수요·비율 차트와 위험 등급을 보여 줍니다.
2. **당일 점검**: 하루 전이 정상인 날은 07:45, 10:45에 초단기예보로 자동 재점검합니다 (기능은 시험 브랜치, 정식 합류 여부는 팀 결정).
3. **배분 권고**: 자원 4종 카드, 배분량, 흡수율, 잔여량. EV 카드는 허브 충전소 수와 가정을 함께 표시하고, **피크 시각에 충전 여력이 큰 충전소 TOP 5**(충전기 수, 여력, 좌표)를 보여 줍니다. 순위는 설치 규모 기준이며 충전소별 혼잡도는 반영하지 못합니다.
4. **승인 흐름**: 결과에 묶인 담당자 승인·반려, 승인 이력 저장. 실제 설비 제어는 없고 모의 알림만 기록합니다.
5. **분석 이력**: 모든 분석·점검 결과와 사용한 데이터 출처를 남깁니다.

### 2.3 편의성
- 설치 없이 브라우저로 사용. 날짜 선택 → 분석 → 결과 확인 → 승인의 4단계.
- 화면은 서버가 확인한 사실만 표시하고, **시연·가정 데이터는 라벨로 구분**합니다 (예: "허브 충전소 2,969곳 운영 중 · 이용률 50% 가정").
- 접근성: 화면 설계 기준(색 대비, 상태 표시)은 `DESIGN.md`, `UX-CONTRACT.md`에 정리했습니다. **[TODO: 실제 대비·키보드 조작 점검 후 결과를 적거나 이 항목을 삭제]**

### 2.4 분석 데이터 활용 방안 (센터 활용)
- 허브 충전소 정보에 **충전 이용 이력(No.136~138)** 을 결합하면 시간대별 실제 이용률로 EV 흡수 용량을 보정할 수 있습니다 (확장).
- 출력제한이 몰리는 9~15시와 충전기 운영 시간을 겹쳐, 지역(읍면동)별 흡수 여력 지도로 확장할 수 있습니다.

## 3. Agent 개발 구성

### 3.1 역할과 목표
**역할**: 도청 에너지 담당 부서 행정담당자를 돕는 **의사결정 지원 Agent**. 데이터를 모으고, 예측하고, 위험을 **조기에 알리고**, 대응안(권고안)을 만들고, 담당자의 승인을 받아 관계기관 통보 초안까지 준비합니다. 출력제한의 판단과 지시는 KPX의 몫입니다.
**목표**: 출력제한일을 놓치지 않으면서(재현율), 불필요한 경보를 줄이는 것(정밀도).

### 3.2 Workflow (LangGraph 상태 그래프)

```
시작 ─┬─ (하루 전) ─▶ 날씨 수집 ─▶ 발전량 예측 ─▶ 수요 예측 ─▶ 위험 판정 ─┬─ 정상 ─▶ 종료
      │                  ▲                                                 ├─ 경계값 ─▶ 새로고침(재수집, 최대 1회) ─┐
      │                  └─────────────────────────────────────────────────┘                                          │
      │                                                                    └─ 주의·위험 ─▶ 배분 권고 ─▶ 알림 초안 ─▶ 담당자 승인 ─▶ 종료
      └─ (당일) ─▶ 당일 점검(초단기예보로 재판정) ─┬─ 정상 ─▶ 종료
                                                    └─ 위험 ─▶ 배분 권고 ─▶ (위와 동일)
```

| 노드 | 하는 일 |
|---|---|
| weather | 기상청 단기예보에서 제주 풍속·기온·하늘상태 수집 |
| prediction | 제주 전체 풍력·태양광 발전량 예측 |
| demand | 제주 시간별 수요 예측 |
| risk | 발전량/수요 비율로 등급 결정, 경계값이면 재수집 요청 |
| intraday_check | 초단기예보·실황으로 당일 재판정 |
| allocate | 피크 1시간 잉여를 자원별로 배분, **EV 용량은 허브 충전소 데이터로 계산** |
| draft / approval | 알림 초안 작성, **담당자 승인 대기(중단 후 재개)** |

작업은 SQLite 체크포인트에 저장되어 서버가 재시작돼도 이어집니다.

### 3.3 사용 모델과 Tool/API

| 구분 | 내용 |
|---|---|
| 발전량 모델 | 제주 전체 단위 풍력·태양광 회귀 모델 (XGBoost 계열, 선택 설치). 풍력 정답은 출력제한 이력을 더해 **"제한이 없었다면의 발전량"** 으로 보정 |
| 수요 모델 | 제주 시간별 수요 회귀 모델. KPX 하루 전 수요예측과 비교 검증 |
| 위험 규칙 | 발전량/수요 비율 임계값(주의 0.40, 위험 0.45). 2021~2024 출력제한 이력으로 보정 |
| Tool 1~6 | 기상 수집, 발전량 예측, 수요 조회, 위험 판정, 배분, 알림 초안 |
| 외부 API | 기상청 단기예보·초단기예보·ASOS(공공데이터포털), **제주데이터허브 충전소 API**, KPX 공개 자료 |
| LLM | **통보문 초안 문장 작성에만 사용(Claude, 선택).** 위험 판단·배분 수치는 예측 모델과 검증된 규칙이 계산하고, LLM은 확정된 수치를 문장으로 옮긴다. LLM 문장의 숫자가 입력과 다르면 템플릿 초안으로 대체하며, 키가 없거나 호출이 실패해도 분석은 템플릿 초안으로 이어진다. 담당자 승인은 그대로 필요하다 |

### 3.4 판단 및 자율 수행 범위

| 구분 | Agent가 스스로 | 사람이 결정 |
|---|---|---|
| 데이터 수집·예측·판정 | ○ | |
| 경계값일 때 재수집(최대 1회) | ○ | |
| 하루 전 정상일 때 당일 재점검(최대 2회) | ○ | |
| 배분 권고안 작성 | ○ | |
| **알림 발송·승인·반려 (관계기관 통보)** | | ○ (도청 담당자 인증 필요) |
| **출력제한 판단·지시** | 하지 않음 | KPX (범위 밖) |
| **실제 설비·충전소 제어** | 하지 않음 | 범위 밖 |

## 5. 개발·탑재 계획

### 5.1 구현 범위와 상태
| 항목 | 상태 |
|---|---|
| 하루 전 분석(예측·판정·배분·승인) | 구현·검증 완료 |
| 허브 충전소 연동 (EV 용량) | 구현·실제 API 호출 확인 |
| 당일 점검, 예보 저장·정기 수집 | 구현 완료, 시험 브랜치 |
| 충전 이력 기반 이용률 보정 | 미구현 (확장) |
| 실제 설비 제어 | 범위 밖 |

### 5.2 기술 환경
- 백엔드: Python 3.11+, FastAPI, LangGraph, SQLite. 프런트: React, TypeScript, Vite.
- **GPU 불필요.** 센터 최소 사양(i7-8700 / GTX 1060 / RAM 32GB)에서 실행 가능한 CPU 기반 구성입니다.
- 데이터 수집은 외부 인터넷과 API 키(기상청, 허브)가 필요합니다. 수집 결과를 파일로 저장해 두면 **오프라인에서도** 분석을 재현할 수 있습니다.

### 5.3 외부 서비스 의존성
기상청 공공데이터포털 API, 제주데이터허브 API, (학습 시) KPX 공개 파일. 키가 없으면 고정 시나리오로 **시연 모드**가 동작하며, 화면에 시연 모드임을 표시합니다.

### 5.4 UI 구성
분석 입력 → 위험 차트·판정 → 배분 권고 카드 → 승인 패널 → 이력 표.

## 6. 검증과 한계 (평가 항목: 결과 신뢰·재현성)

### 6.1 검증 결과
**[실측] 과거 날짜 vs 실제 출력제한일** (2023-01-01 ~ 2024-05-30, 494일, 점검 기간을 학습에서 완전히 제외한 모델):

| 판정 | 판정한 날 | 출력제한일 포착(재현율) | 판정 중 실제 제한일(정밀도) |
|---|---|---|---|
| 주의 이상 | 176일 | **80.8%** (135/167) | **76.7%** |
| 위험 | 124일 | 61.1% | 82.3% |
| 이전 규칙(잉여 150/200MWh 기준) | 0일 | 0% | — |

- 달력만 쓰는 단순 규칙(3~5월·10월 전부 위험)보다 포착은 6.5%p, 정밀도는 18.5%p 높고 오경보는 절반 이하입니다 (89일 → 41일).
- 적중한 날의 예측 피크 시간은 실제 제어 시간과 ±1시간 이내가 97.0%입니다.
- 테스트: 백엔드 190개, 프런트 18개 통과.

**[실측] 허브 일별 기상으로 기상청 관측 교차검증** (2024-01 ~ 2025-03, 454일): 허브 기온(해발 100 m 미만 17곳 평균)과 ASOS 제주 일평균 기온의 상관 **0.996**, 평균 편향 −0.5℃, MAE 0.7℃. 수요 모델에 입력 기온만 허브 값으로 바꾸면 **보정 없이는 오차가 늘고**(2024년 MAE 36.5 → 40.4 MW), **편향을 보정하면 ASOS와 같은 수준**이었다(2025년 1~3월 89일, 42.9 대 41.0 MW). 상세는 `docs/guides/hub-weather-check.md`.

### 6.2 한계 (숨기지 않고 밝힙니다)
1. **날씨는 실측을 예보 자리에 넣어** 점검했습니다. 과거 예보 이력이 없기 때문입니다. 예보 오차를 **[시뮬레이션]** 으로 섞으면 정밀도가 76.7% → 49~63%로 떨어집니다. 예보 이력이 쌓이면 임계값을 다시 맞춰야 합니다.
2. **당일 점검의 효과(포착 약 93%)는 [시뮬레이션]** 이며 실측으로 확인된 상승이 아닙니다.
3. 제주 출력제한 이력은 **2024-06 초에 끝납니다.** 이후 입찰제 영향은 확인하지 못했습니다.
4. **EV 배분량은 낙관적일 수 있습니다.** 충전기 출력(완속 7kW, 급속 50kW)과 남는 전력을 받아 줄 수 있는 비율(설치 용량의 50%)은 **[가정]** 이며, 허브 데이터 기준일은 2025-09입니다. 나머지 자원(ESS, 수소)의 용량은 시연 추정치입니다.
5. 허브 일별 기상은 **2025-03 말 이후 비어 있어** 서비스 입력이나 학습 입력으로 쓸 수 없고 교차검증에만 썼습니다. 검증 구간은 겨울~초봄 89일뿐이라 봄·가을 출력제한 시기는 확인하지 못했습니다.
6. 실시간 충전기 사용 여부는 알 수 없습니다. 이 서비스는 **권고안**이며 설비 상태를 확인한 제어안이 아닙니다.
