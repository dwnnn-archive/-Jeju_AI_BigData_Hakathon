## 1. 구현 목표 (분석 주제의 타당성과 창의성)

### 1.1 문제
제주는 풍력·태양광이 많아 수요가 적은 봄·가을 낮에 발전량이 수요를 넘습니다. 이때 계통 안정을 위해 발전기를 강제로 줄입니다. 제주 풍력은 2021-01 ~ 2024-05에 **335일, 1,567시간, 73,224 MWh**가 줄었습니다([실측], KPX 출력제어 이력). 2024년 한 해에는 연간 **56일** 출력제어가 있었고(풍력·태양광 제어 51회, 태양광 차단 5회), 현장에서는 중앙급전 발전기의 최소출력 하향과 연계선 역송으로 먼저 완화해 **완화율이 86.4%**(2023년 76.0%)였습니다([보도·공시], [KPX 「2024년 연간 제주지역 전력계통 운영실적」](https://www.kpx.or.kr/board.es?mid=a10102090000&bid=0159&act=view&list_no=74566&tag=&nPage=1)). 버려지는 전기를 줄이려면 **하루 전에 위험을 알고 저장·소비처를 준비**해야 합니다.

### 1.2 이 서비스가 하는 일

| 목표 | 설명 |
|---|---|
| 하루 전 위험 판정 | 기상예보 → 제주 풍력·태양광 발전량 예측, 수요 예측 → **발전량 ÷ 수요 비율**로 정상·주의·위험 산정 |
| 당일 재점검 | 하루 전에 "정상"이던 날을 초단기예보로 다시 점검해 놓침을 줄임 |
| 자원 배분(대응 후보 제안) | 위험 시 피크 1시간의 남는 전력을 전기차 충전(EV) 먼저, 이어서 BESS·VPP·P2X(확장 후보) 순으로 얼마씩 보낼지 제안, 받지 못하는 **잔여 전력도 숨기지 않고 표시** |
| 사람이 결정 | 통보문 초안은 Agent가 쓰고, 담당자가 문구를 확인하고(수정은 AI가 새로 작성) **'확인했습니다'를 기록한 뒤 기관의 문자 발송 시스템에서 직접 발송**. Agent는 제어 명령과 문자 발송을 하지 않음 |

### 1.3 사용자와 역할의 경계
**제주특별자치도청 에너지 담당 부서의 담당자**(IT 비전문가)가 주 사용자이고, Agent는 이 담당자를 돕는 **보조 도우미**입니다. Agent가 위험을 알리고 통보문 **초안을 만들어 두면**, 담당자가 문구를 확인하고 **발송 여부를 정합니다**. 도청의 역할은 **조기 인지 → 대응안 검토 → 통보문 확인·발송 → 관계기관 통보**까지이고, **출력제한의 판단과 지시는 KPX의 역할**입니다. 그래서 Agent의 위험 등급은 도청이 쓰는 조기 인지용 참고 정보이며, 설비를 직접 제어하지 않습니다.

| 역할 | 누구 | 비고 |
|---|---|---|
| 예상 사용자(시연 페르소나, 주 사용자) | **도청 에너지 담당 부서 담당자** | 상황 인지, 통보문 확인·기록, 충전소·사업자 협조 요청 초안 확인 |
| 정보 공유·확장 경로 | 계통 운영 기관(KPX, 한전 등) | 확장 시 실시간 데이터 연동 |
| 수혜자 | 전기차 이용자, 충전소 운영자, 재생에너지 사업자 | 사전 정보 |
| 귀속 | 제주빅데이터센터 | 산출물 귀속 |

위 사용자는 **예상 사용자(시연 페르소나)**입니다. 실제 도청 담당자의 사용성 확인은 5.3의 시범 운영 계획에 두었습니다.

### 1.4 차별점
- **데이터가 결과를 바꿉니다.** 충전기 출력·이용률을 가정하지 않고 허브 충전 이력으로 실측해 EV 용량을 계산합니다.
- **한계를 숫자로 보여 줍니다.** 같은 과거 날짜에 용량 기준만 바꿔 "공개된 제주 설비 규모(EV는 고정 40 MWh로 볼 때)로는 위험으로 판정한 날의 약 27.8%에서 잉여를 다 받지 못한다"는 결과를 냅니다. 이는 ESS·수소 확충이 필요하다는 근거로 읽을 수 있습니다.
- **LLM은 문장과 도구 선택을 맡고, 수치는 코드가 정합니다.** 통보문 문장을 쓰고, 담당자의 질문에는 읽기 전용 도구 6개 중 필요한 것을 골라 조회한 값으로 답합니다. 답의 숫자가 조회 결과에 없으면 쓰이지 않습니다.

### 1.5 선행 자료와의 관계
- **[선행연구] KEA 에너지 이슈 브리핑 제221호(2023-08-28)**: 제주 풍력·태양광 출력제한이 2018년 15건·1,365 MWh에서 2022년 132건·28,853 MWh로 늘었다고 정리하고, 대응으로 예측 정확도 제고, 잉여전력을 흡수하는 장치(ESS·P2G·P2H), 잉여 시간대에 수요를 만드는 제도(플러스 DR)를 제시했습니다.
- **[선행연구] 한국은행 이슈노트 제2025-35호(2025-11-18)**: 전력계통 최적화 모델(MOST)로 BESS, 전기차, 온도 민감 수요를 비교해, 한 자원만으로는 한낮 출력제한을 줄이기 부족하고 함께 쓰면 상당히 개선되며 제11차 전력수급기본계획 기준으로 전기차의 효과가 BESS보다 컸다고 보고했습니다.
- **[선행연구] 전우영·박상훈(2026), 『신재생에너지』 22권 2호(DOI 10.7849/ksnre.2026.0011)**: 제주에서 BESS와 육지 연계선(HVDC)이 출력제한을 얼마나 줄이는지 시뮬레이션하고, 호남권 혼잡으로 역송이 제한되면 출력제한이 늘어난다는 점과 봄철에 집중된다는 점을 보고했습니다. 열람 제한으로 초록 수준만 확인했습니다.
- **[공식 공고] [KPX 「제주 출력제어 전망 안내」(2025-02-17 게시)](https://new.kpx.or.kr/board.es?mid=a10109050000&bid=0216&tag=&act=view&list_no=74332)**: KPX는 비중앙 발전기 출력제어를 예정일·시간, 수급전망, 제한사유로 알리고 "대상 발전소는 **전일 18시까지 사전고지**, 기상·수요 변동에 따라 변동될 수 있다"고 안내합니다. 이 서비스의 하루 전 분석(17:30)은 이 사전고지 **전에** 담당자가 위험을 미리 알고 충전소 등과 협조를 준비하도록 돕고, 통보문도 같은 항목(일시·수급·사유·변동 가능)으로 씁니다. 출력제어 지시 자체는 KPX의 몫입니다.
- **[보도·공식] [ZDNet Korea(2021-09-30)](https://zdnet.co.kr/view/?no=20210930135620), 기후에너지환경부·한국전력 보도참고자료 「계절·시간대별 전기요금 체계 개편안 공개」(2026-03-13), [KEPCO 웹진 2026년 8월호](https://www.kepco.co.kr/KEPCO_FILE/html/2026_08/issue.html)**: 한전은 2021년 제주 한전 소유 전기차 충전기 400여기를 플러스DR(수요가 부족할 때 전력 사용을 늘린 만큼 보상하는 제도) 수요자원으로 등록했고, 제주도·그리드위즈와 "전기차 충전기 활용 플러스DR 시범사업" 협약을 맺었으며 **제주도는 제도 홍보와 개선사항 발굴**을 맡았습니다. 2026년에는 봄(3~5월)·가을(9~10월) 주말·공휴일 11~14시 전력량요금을 50% 할인하고(전기차 충전전력은 4월 16일 시행, 2030-12-31까지) 플러스DR과 함께 적용하면 평일 최고요금의 20~30% 수준(31~50원/kWh)입니다. 이는 달력으로 고정된 규칙이고, 이 서비스는 **실제 위험일**을 하루 전에 알려 그 규칙이 닿지 않는 평일 제한(과거 제한일의 63.5%)까지 충전소 운영자·이용자에게 협조를 요청하는 데 씁니다.
- **이 서비스와의 관계**: 위 연구는 연 단위 계통 시뮬레이션이고, 이 서비스는 하루 단위로 위험을 미리 알리는 참고 도구입니다. 우리 결과를 검증한 근거가 아니라, 문제의 구조(잉여전력 흡수, 전기차의 비중, 연계선 의존, 봄철 집중)가 같은 방향이라는 선행 자료로 참고했습니다. 배분 순서는 이 연구들에서 나온 것이 아니라 5.2에 적은 설계 규칙입니다.

**데이터 품질 사례**
- 충전기 번호(`evChargerId`)는 충전소마다 1번부터 다시 시작해, 이것만으로 세면 충전기가 25기로 잘못 계산되어 점유율이 100%로 나왔습니다. **(충전소, 충전기) 쌍으로 구분**하도록 고쳐 실제 742~841기를 얻었고 회귀 테스트를 추가했습니다.
- 충전소 운영 시간이 가이드(`00:00`)와 달리 `0:00`, `24:00:00`으로 내려와 정규화했고, 충전 방식별로 같은 충전소가 여러 행으로 내려와 266행을 합쳤습니다(합치지 않으면 충전기 수가 약 8% 부풀려집니다).
- 허브 일별 기상은 2025-03 말 이후 응답이 비어 있어 **서비스 입력이 아니라 교차검증에만** 썼습니다. 일별 충전 이력은 시간·요일 정보가 없어 점유율에는 쓰지 않고, **월별 합계와 일치하는지**(충전량 −0.00%, 횟수 +0.00%)와 날짜별 변동·이용 증가를 확인하는 데 썼습니다.
- 허브 API의 **일일 호출 한도**를 고려해 받은 달을 저장하고, 호출 횟수를 로그로 남기며, 한 번에 받을 달 수를 제한했습니다(재실행해도 같은 달을 다시 호출하지 않음).

## 3. Agent 개발 구성 (AI Agent 기술성과 완성도)

### 3.1 구조
Agent는 **도구 6개를 LangGraph 상태 그래프로 엮어** 판단하고, 담당자의 확인을 받아 마무리합니다. 계산은 코드와 모델이, 문장과 질문 응대(도구 선택)는 LLM이, 결정은 사람이 맡습니다.

| 배분 용량 | **EV 109.0 MWh(허브 데이터, 1순위)** · 확장 후보: BESS 37.7(제주 ESS 계량 실적의 시간당 최대 충전량 [실측]) · VPP 3.2(제주 플러스DR 증대 실적 [실측] 하한) · P2X 3.3(행원 그린수소 실증단지 3.3 MW [보도]) |
| LLM 1: 통보문 | **통보문 문장 작성(Claude, 선택)**. 확정 수치만 전달하고, 숫자가 입력과 다르거나 핵심 값이 빠지면 한 번 더 받고, 그래도 실패하거나 키가 없거나 호출이 실패하면 **템플릿 초안**으로 대체합니다. 이 경로에는 허브 원본과 충전소 이름을 보내지 않습니다. |
| LLM 2: 질문 응답 | **담당자의 질문에 Claude가 도구를 골라 답합니다(선택)**. 도구는 위험 판정, 시간별 예측, 자원 배분, 충전소, 데이터 출처, 검토 상태 조회의 **읽기 전용 6개**이고 승인·발송·설비 제어 도구는 없습니다. 도구는 숫자를 문자열로 만들어 돌려주고, 답의 숫자가 조회 결과나 질문에 없으면 한 번 더 받은 뒤 **기본(키워드) 답변**으로 대체합니다. 키가 없거나 호출이 실패해도 마찬가지입니다. 화면은 "AI 답변"과 "기본 답변"을 구분하고 조회한 도구를 보여 줍니다. 충전소 질문에는 충전소 이름·충전기 수·여력(공개 데이터)이 도구 결과로 전달됩니다. |

### 3.5 안정적 수행
- 작업은 SQLite 체크포인트에 저장되어 **서버가 재시작돼도 이어지고**, 확인 기록은 결과와 묶여 있어 결과가 바뀌면 이전 확인은 적용되지 않습니다.
- 응답이 사라져도 실패로 단정하지 않고 **상태 확인 불가**로 표시하며, 재요청은 같은 ID로 중복 작업을 막습니다.
- live 결과는 모델과 가용량이 운영 환경에서 검증되지 않았으므로(과거 자료 검증은 마쳤습니다) **실제 발송 경로를 차단**합니다(통보문 확인 기록과 복사만 가능). 외부 조회가 실패해도 시연 값으로 몰래 바꾸지 않고 실패를 표시합니다.
- 테스트 **백엔드 243개, 화면 39개, 브라우저 종단 9개**. 외부 네트워크 없이 실행되며 복구·동시 승인·중복 방지·LLM 폴백을 포함합니다.

## 4. 편의성과 실용성

### 4.1 사용 흐름
설치 없이 브라우저로 사용합니다. **조건 선택 → 분석 요청**을 한 뒤 **발전량 예측 → 자원 배분 → 통보문 확인**의 3단계 화면에서 결과를 확인하고, 통보문을 작성·확인한 뒤 기관의 문자 발송 시스템으로 보냅니다.

<!--FIG:flow4-->

<!--FIG:shots-->

- **당일 점검 버튼**: 하루 전 판정이 정상인 오늘 날짜의 결과가 확인되면 "당일 점검 요청" 버튼이 나타나 같은 조건으로 1차, 2차 점검을 요청합니다(하루 최대 2회, 서버가 규칙을 강제). 시연 조건 "당일 위험 전환"을 고르면 하루 전 정상 → 1차 정상 → 2차 위험 → 통보문 확인 단계까지 한 화면에서 따라갈 수 있습니다.
- **하루 업무 흐름**: 발전량 예측 화면 맨 위에 담당자의 하루 단계(전날 17:30 분석 → 07:45·10:45 점검 → 담당자 통보문 확인 → 통보 → 09~15시 피크)를 보여 주고, 지금 보는 분석이 어느 단계인지 표시합니다. 단계 표시는 화면의 위치일 뿐 다른 날의 진행을 뜻하지 않습니다.
- 화면은 서버가 확인한 사실만 표시하고, **시연·가정 데이터에는 라벨**을 붙입니다(예: "허브 충전소 2,969곳 운영 중 · 충전 이력(2021~2022) 기반 이용률"). 배분 카드에는 자원별 근거 표시(EV 허브 데이터, BESS·VPP 실적 기반 하한, P2X 보도 기준)를 달아 어느 숫자를 믿고 어느 숫자를 확인해야 하는지 구분합니다.
- 위험일에는 **충전 여력이 큰 충전소 TOP 5**(충전기 수, 여력, 좌표)를 함께 보여 줍니다. 순위는 설치 규모 기준이며 충전소별 혼잡도는 반영하지 못한다고 화면에 적었습니다.
- 접근성: 자동 검사(axe)에서 검사한 데스크톱 결과·통보문 확인 화면·모바일 화면의 위반이 0건이었고, 키보드(Esc로 닫기, 포커스 복원)와 390px 모바일을 확인했습니다. 전체 WCAG 적합성 인증은 아닙니다.

**[실측] 허브 일별 기상 교차검증**: 허브 기온과 ASOS 상관 0.996. 수요 모델에 입력 기온만 허브 값으로 바꾸면 보정 없이는 오차가 늘고(2024년 MAE 36.5 → 40.4 MW), 편향 보정 시 ASOS와 같은 수준(2025년 1~3월 89일, 42.9 대 41.0 MW)입니다.

### 5.2 한계 (숨기지 않고 밝힙니다)
1. **날씨는 실측을 예보 자리에 넣어** 점검했습니다(과거 예보 이력 없음). 예보 오차를 [시뮬레이션]으로 섞으면 정밀도가 76.7% → 49~63%로 떨어집니다.
2. **당일 점검의 효과(포착 81~83% → 약 93%)는 [시뮬레이션]**이며 실측 상승이 아닙니다.
3. 제주 출력제한 이력은 **2024-06 초에 끝납니다.** KPX 운영실적 보고서에 따르면 2024-06-01부터 재생E 입찰제가 시작되어, 입찰제 참여 발전기의 출력 감소는 출력제어 실적에 반영되지 않기 때문입니다. ([KPX 「2024년 연간 제주지역 전력계통 운영실적」](https://www.kpx.or.kr/board.es?mid=a10102090000&bid=0159&act=view&list_no=74566&tag=&nPage=1))
4. **충전 이력은 2021-04, 2022-04의 과거 자료**입니다. 이후 전기차가 늘었다면 EV 용량(109.0 MWh)은 낙관적일 수 있고, 이력의 충전소는 허브 3,180곳의 일부입니다. 일별 이력에서 하루 평균 충전량이 1년 만에 **27% 늘었으므로**, 점유율을 2~3배로 키워도 EV 용량은 75~92 MWh, 위험일 흡수율은 52~59%임을 계산해 두었습니다(별첨 명세서 1.3절).
5. **BESS는 실적 기반 하한**이고, **P2X 3.3 MWh는 [보도]** 수치(공식 통계 아님), **VPP는 제주 플러스DR 증대 실적을 근거로 3.2 MWh를 씁니다**([KPX 수요자원거래시장 현황 및 운영정보(2025.6)](https://new.kpx.or.kr/boardDownload.es?bid=0088&list_no=75203&seq=1): 실시간 시장 2023-04 월 평균 시간당 증대량 73.7 MWh ÷ 23시간의 최댓값이고, 하루 전·실시간 전체 평균은 약 1.8~3.0 MWh/h). 실제 이행된 양이라 흡수 가능량의 **하한**이고, 플러스DR에는 전기차 충전기 참여분이 포함되어 EV 용량과 일부 겹칠 수 있습니다. 제주 VPP 운영 규모 약 203.4 MW([이코리아, 2025-06-16](https://www.ekoreanews.co.kr/news/articleView.html?idxno=80606))는 주로 발전자원을 묶은 값이라 흡수 용량으로 쓰지 않았습니다.
6. 이 서비스의 배분은 **참고용 대응 후보 제안**입니다. 도청이 배분을 정하는 것이 아니며, 설비 상태를 확인한 제어안도 아닙니다.
7. **LLM이 지휘하는 범위는 질문 응답과 문장 작성입니다.** 분석 파이프라인의 순서와 분기는 고정된 그래프이고, 재현성과 복구를 위해 의도한 설계입니다. 질문 응답의 정확도는 대표 질문을 실제로 돌려 확인한 수준이며 통계적으로 검증하지 않았습니다.
8. **원래 의도와 달리 출력제한 물량이나 제3연계선 용량을 직접 계산하지는 않습니다.** 이 서비스의 "잉여전력"은 발전량에서 수요의 40%를 뺀 값이고, 시민 사용량은 수요 예측에 이미 포함되어 있습니다. 40%·45% 기준은 과거 출력제한일(2023-01~2024-05)과 맞춰 정한 경험값이며, 연계선의 정격 용량은 공개되어 있으나([보도] 제1·2·3연계선 300·400·200 MW, [산업통상자원부 자료](https://www.motir.go.kr/attach/down/095a2dda9c864e1d90d751f7668a1117/53f4db8095bb881d66d862db4484bcb0)) 시간대별 연계선 수전전력도 KPX가 [공개](https://www.data.go.kr/data/15100403/fileData.do)합니다(2026-01~09, 273일). 이 자료는 출력제한 이력(~2024-05)과 기간이 겹치지 않아 판정 검증에는 쓰지 못했고 위험 판정에도 반영하지 않았습니다. 참고로 [실측] 2026년 자료에서는 제주에서 육지로 내보내는 방향으로 해석되는 음수 값이 2~5월 낮 시간대에 몰려 있었습니다(세 연계선 합계가 음수인 시간이 있던 날의 비율: 3월 52%, 4월 43%, 5월 74%, 7~9월 0%. 부호 규칙은 파일에 명시되지 않아 추정). 화력발전소의 최소 출력 조건은 데이터가 없어 반영하지 못했습니다. 그래서 결과는 출력제한 **가능성**의 조기 인지용이고, 실제 제한 여부와 물량은 KPX가 정합니다.
9. **배분은 전기차(EV) → BESS → VPP → P2X 순서로, 앞 자원이 다 차야 다음으로 넘어갑니다.** EV를 먼저 채우는 이유는 제주데이터허브의 충전소 정보와 충전 이력으로 용량을 직접 계산한 자원이고, 충전소 운영자와 전기차 이용자에게 충전 시간을 옮겨 달라고 요청하는 것이 이 서비스의 기본 대응이기 때문입니다. BESS·VPP·P2X는 EV로 다 담지 못할 때 보태는 **확장 후보**이며, 실제 설비 연동과 사업자 확인 뒤 확장합니다. 나머지의 순서(BESS → VPP → P2X)는 응답 속도와 제어의 확실성을 기준으로 정한 설계 규칙이고, 자원별 실제 응답 시간 자료로 검증하지는 못했습니다.
10. **11월에는 위험 판정이 실제 출력제한보다 많습니다.** 2021~2023년 11월에는 실제 발전량/수요 비율이 기준(0.40) 이상인 날이 해마다 19·19·21일이었지만 출력제한은 1·13·5일에 그쳤습니다(같은 비율에서 3~5월은 대체로 70% 이상 제한이 걸렸습니다). 모델이 비율을 과대 예측한 것이 아니라(2023년 11월 예측이 실제보다 평균 0.02 낮음) 같은 비율에서도 제한 여부가 달라지는 계통 상황(연계선 가동·역송 여력, 화력발전소 최소출력)의 영향으로 보이나, 연계선 자료가 이력과 겹치지 않아 데이터로 확인하지 못한 추정입니다.

## 6. 개발·탑재 계획과 기대 효과

### 6.1 구현 범위

| 구현함 | 구현하지 않음 (범위 밖) |
|---|---|
| 하루 전·당일 위험 판정, 시간별 예측, 자원 배분(EV 우선), 충전소 TOP 5, 통보문 작성·수정·확인 기록, 질문 응답, 분석 이력, 시연·live 모드 | 출력제한 판단·지시(KPX), 설비·충전소 제어, 문자 자동 발송(담당자가 기관 시스템으로 발송), 충전소별 실시간 혼잡도 |

### 6.2 기술 환경과 UI 구성

- **기술**: 백엔드 Python 3.11+ · FastAPI · LangGraph · SQLite, 화면 React · TypeScript · Vite. 설치 없이 브라우저로 사용합니다.
- **UI 구성**: 소개 → 대시보드(위험 등급·다음 단계) → 발전량 예측(시간별 그래프, 하루 업무 단계) → 자원 배분(EV 우선 순서, 충전소 TOP 5) → 통보문(요약, 수신 대상, 원문, 수정·복사, 확인 기록) → 분석 이력 · 데이터 출처 · 질문 응답 창.

### 6.3 센터 실행환경과 외부 서비스 의존성

- **실행 환경**: GPU를 쓰지 않으며(모델은 XGBoost 회귀) 프로세스는 백엔드 1개와 화면 서버 1개, 저장소는 SQLite 파일 하나입니다. 이 PC에서 실행 중인 백엔드의 메모리는 약 60 MB, 화면 개발 서버는 약 64 MB였습니다(유휴 상태 측정이며 분석 중 부하 측정은 아님). 센터 최소 사양(i7-8700 / GTX 1060 / RAM 32GB / VRAM 3072MB)에서 직접 측정하지는 못했으나, 요구 자원이 사양의 일부이므로 실행에 무리가 없을 것으로 판단합니다.
- **외부 서비스 의존성과 장애 시 동작**

| 서비스 | 용도 | 접속 불가·키 없음일 때 |
|---|---|---|
| 기상청 API | 단기예보·초단기·실황 | live 분석 실패를 표시하고 시연 값으로 바꾸지 않음. 시연 모드는 영향 없음 |
| 제주데이터허브 API | 충전소·충전 이력 | 받아 둔 로컬 저장분 사용, 없으면 시연 모드 표시 |
| Claude API (선택) | 통보문 문장, 질문 응답 | 템플릿 초안과 기본(키워드) 답변으로 대체 |

센터망이 외부 접속을 막는 경우에도 **시연 모드와 템플릿 통보문은 인터넷 없이 동작**하며, live 분석에는 기상청·허브 접속이 필요합니다.

### 6.4 기대 효과와 확장

- **기대 효과**: 하루 전 위험 인지로 저장·소비처 준비 시간을 확보하고, 설비 규모의 부족분(잔여 전력)을 근거로 ESS·수소 확충 논의에 데이터를 제공합니다.
- **확장**: 통보문 수신자(충전소 운영자)를 플러스DR 입찰·할인 안내와 연결, 예보 이력 기반 임계값 재보정, 읍면동별 흡수 여력 지도, 충전소별 우선순위, 실시간 충전기·ESS 상태 연동.
