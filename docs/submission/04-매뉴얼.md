# 실행·사용 매뉴얼

> 제주 AI·빅데이터 활용 AI Agent 개발 챌린지 제출용 · 팀: **Synerge_Lab팀**
> 대상: 이 프로젝트를 처음 받아 실행·재현해 보는 사람 (개발자 또는 심사위원)

## 0. 한눈에 보기

| 하고 싶은 일 | 필요한 것 | 걸리는 시간 |
|---|---|---|
| **시연 모드로 화면 보기** | Python 3.11+, uv, Node.js 22, 인터넷(패키지 설치용) | 약 10분 |
| 실제 데이터로 분석 (live) | 위 + API 키(기상청, 제주데이터허브) | 약 30분 |
| 허브 데이터 수집·검증 재현 | 허브 프로젝트 키, 하루 호출 한도 확인 | 수 분~수십 분 |
| 테스트·통계 재현 | 위의 설치만 | 약 1분 |

- **GPU는 필요 없습니다.** CPU만으로 실행됩니다.
- **키가 없어도 시연 모드는 동작합니다.** 시연 모드의 발전량은 고정 시나리오이고 화면에 "시연 모드"가 표시됩니다.
- 실제 설비를 제어하는 기능은 없습니다. 시연의 발송 확정은 모의 알림만 기록하고, 실제 문자는 보내지 않습니다.

## 1. 설치와 실행 (시연 모드)

터미널 두 개가 필요합니다.

**터미널 1: 백엔드**

```bash
cd backend
uv sync --frozen --extra dev --extra ml
cp .env.example .env
```

`backend/.env`를 열어 `APPROVER_TOKEN=` 줄의 `#`를 지우고 **직접 만든 긴 문자열**을 넣습니다. 통보문 발송 확정·보류에 쓰는 담당자 인증 토큰입니다. 설정하지 않으면 발송 확정과 보류가 차단됩니다.

```bash
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

정상이면 `http://127.0.0.1:8000/health`가 `{"status":"ok", ...}`를 돌려줍니다.

**터미널 2: 화면**

```bash
cd frontend
npm ci
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다. API 문서는 `http://localhost:8000/docs`입니다.

> 백엔드는 반드시 `backend/` 폴더에서 실행합니다(상대 경로로 `.env`와 `runtime/`을 찾습니다).

## 2. 화면 사용법

화면 위쪽 메뉴는 **소개 / 대시보드 / 분석 / 분석 이력**이고 오른쪽에 **연결 설정**과 **로그인**이 있습니다. **분석**은 세 단계(**발전량 예측 → 자원 배분 → 통보문 확인**)로 이루어지며, 화면의 단계 탭이나 "다음 단계" 버튼으로 이동합니다.

| 메뉴 | 내용 |
|---|---|
| 소개 | 서비스 소개 화면입니다. |
| 대시보드 | 날짜를 고르고 분석을 요청하면 피크 시간 잉여전력, 흡수 가능 비율, 배분 후 잔여량과 하루의 전력 흐름을 한 화면에 요약합니다. |
| 분석 | 아래 표의 1~4단계가 여기서 이루어집니다. |
| 분석 이력 | 지난 분석과 사용한 데이터 출처를 보고, 항목을 눌러 결과를 다시 엽니다. |

**로그인(담당자)**: 오른쪽 위 **로그인**에서 담당자 ID(기본 `local-officer`, `.env`의 `APPROVER_ID`)와 인증 토큰(`.env`의 `APPROVER_TOKEN`)을 입력합니다. 로그인하면 발송 확정·보류 때 토큰을 다시 입력하지 않습니다. 로그인 정보는 메모리에만 있어서 새로고침하면 로그아웃됩니다. 로그인하지 않아도 분석 결과는 볼 수 있고, 발송 확정·보류할 때만 토큰이 필요합니다.

| 단계 | 하는 일 | 확인할 것 |
|---|---|---|
| 1. 입력 | **분석** 메뉴에서 예측 대상일(달력), 분석 지역, 데이터 모드를 고르고 **분석 요청**을 누릅니다. 처음에는 **외부 데이터 · 운영 검증 전**이 선택되어 있으며(기상청 키와 학습한 모델이 필요), 키·모델이 없는 PC에서는 **시연 데이터**를 고른 뒤 시연 조건(**위험일**)을 선택합니다. | 시연 데이터를 고르면 조건 아래에 "시연 모드" 안내가 보입니다. |
| 2. 결과 | 상태가 "계산 완료 · 검토 필요"가 되면 **발전량 예측** 단계에 시간별 발전량·수요 차트, 24시간 위험 띠, 검토 요약이 나옵니다. | 위험 등급(위험), 피크 잉여전력 230.0 MWh, 피크 시간 12:00~13:00 |
| 3. 배분 | **자원 배분** 단계에서 BESS / VPP / P2X / EV 카드와 **충전소 TOP 5**를 봅니다. | 흡수 제안 180.0 MWh(78.3%), 잔여 50.0 MWh, 수소 환산 약 43 kg |
| 4. 통보문 | **통보문 확인** 단계(통보문 발송 도우미)에는 **재측정**과 **통보문 작성** 버튼이 있습니다. 결과가 의심스러우면 재측정으로 같은 조건을 다시 분석하고, **통보문 작성**을 누르면 그제서야 통보문 초안과 수신 대상(문자 발송을 승인한 시민, 관내 충전소 등 운영자·재생에너지 사업자)이 나옵니다. 문안이 마음에 들지 않으면 **수정**을 눌러 AI가 새로 쓰게 하고, **통보문 복사**로 기관의 문자 시스템에 붙여 넣습니다. | AI 키가 없으면 수정해도 기본 문안이 나오고 그 사실이 표시됩니다. 시연에서는 실제 문자가 나가지 않고 실제 설비 동작도 없습니다. |
| 5. 이력 | **분석 이력**에서 지난 분석을 봅니다. | |

**시연 조건**을 바꿔 보면 흐름이 달라집니다(데이터 모드가 시연일 때만 나타납니다).

| 시연 조건 | 기대 결과 |
|---|---|
| 위험일 | 위험 등급, 대응 후보 제안과 통보문 초안, 통보문 작성 대기 (잉여 230.0 MWh) |
| 정상일 | 위험 없음, 요약만 저장하고 종료 |
| 경계 재조회 | 위험 비율이 0.43~0.45라서 1회 다시 계산한 뒤 판정 |
| 경계 유지 | 다시 계산해도 경계가 해소되지 않아 승인이 막힘 |
| 당일 위험 전환 | 하루 전 정상 → 당일 1차 정상 → 2차 위험 → 승인 대기 (대상일이 오늘로 자동 설정) |

**당일 점검**(하루 전이 정상이던 날을 초단기예보로 재판정, 최대 2회)은 분석 화면의 **당일 점검 요청** 버튼으로 실행합니다. 버튼은 오늘 날짜의 하루 전 결과가 "정상"으로 확인됐을 때만 나타납니다. 시연 조건에서 **당일 위험 전환**을 고르고 분석 요청 → 당일 점검 요청 → 한 번 더 당일 점검 요청 순서로 누르면 1차(정상), 2차(위험), 승인 대기까지 확인합니다. 정해진 시각 실행은 `scripts/run_intraday.py`(외부 스케줄러용)로도 가능합니다(`docs/guides/intraday-check.md`).

**발전량 예측** 단계의 **담당자 하루 업무 흐름**은 전날 17:30 분석부터 피크 시간대까지의 단계를 보여 주고, 지금 보는 분석의 위치를 표시합니다. **자원 배분** 카드의 **가정값·보도 기준·자료 기반** 표시는 각 용량의 근거 수준입니다(VPP는 근거 자료가 없는 가정값).

화면의 숫자는 서버가 확인한 사실만 표시하고, **시연·가정 값에는 라벨**이 붙습니다.

## 3. 실제 데이터로 실행 (live, 선택)

`backend/.env`에 아래 키를 넣습니다. **키는 저장소에 올리지 않습니다.**

| 환경변수 | 용도 | 발급 |
|---|---|---|
| `JEJUHUB_PROJECT_KEY` | 제주데이터허브 API (충전소, 충전 이력, 일별 기상) | 허브 로그인 → 데이터를 프로젝트에 담기 → 마이페이지 > 프로젝트 관리 |
| `KMA_API_KEY` | 기상청 단기·초단기예보 | 공공데이터포털 활용신청 (공공데이터포털 키면 `KMA_BASE_URL`, `KMA_AUTH_PARAM=serviceKey`도 설정, `.env.example` 참고) |
| `ASOS_API_KEY` | 과거 실측 기상(학습용) | 공공데이터포털 활용신청 |
| `KPX_GEN_API_KEY` | KPX 발전량 odcloud API(선택) | 공공데이터포털 활용신청 |
| `ANTHROPIC_API_KEY` | 통보문 초안을 Claude가 문장으로 작성(선택) | Anthropic Console (구독과 별도 결제) |

live 모드의 예측 모델은 `JEJU_MODEL_DIR`(발전량), `JEJU_DEMAND_MODEL_DIR`(수요)로 지정합니다. 학습 방법은 5절이며, 학습한 모델을 `runtime/models/`에 만들었다면 `backend/.env`에 아래처럼 적고 백엔드를 다시 시작합니다.

```
JEJU_MODEL_DIR=runtime/models/jeju
JEJU_DEMAND_MODEL_DIR=runtime/models/demand
```

**화면에서 외부 데이터로 분석하기**: **분석** 메뉴에서 데이터 모드가 **외부 데이터 · 운영 검증 전**인지 확인하고(기본값입니다. 시연 데이터로 바꿨다면 다시 선택) 예측 대상일을 고른 뒤 **분석 요청**을 누릅니다(시연 조건은 사라집니다). 기상은 기상청 예보, 발전량·수요는 학습한 모델로 계산하고, 결과 아래 **데이터 출처와 실행 기록**에서 "시연/대체 데이터"가 아닌 "외부 조회 또는 추정"으로 표시된 것을 확인합니다. 외부 데이터 분석은 몇 초(약 10초) 걸립니다. 모델이나 키가 없으면 시연 값으로 바꾸지 않고 실패하며, `ALLOW_MOCK_FALLBACK=true`를 켠 경우에만 시연 값으로 대체합니다.

**live 결과는 모델과 가용량이 운영 환경에서 검증되지 않았으므로(과거 자료 검증은 마쳤습니다) 승인과 실제 발송이 차단됩니다.** 이는 의도된 안전장치입니다.

### LLM 켜기 / 끄기 (통보문 초안과 질문 응답)

- 켜기: `backend/.env`에 `ANTHROPIC_API_KEY`를 넣고 `uv sync --frozen --extra dev --extra ml --extra llm`을 실행합니다. 모델은 `LLM_MODEL`로 바꿀 수 있습니다(기본 `claude-opus-5-5`).
- 끄기: 키를 지웁니다. 템플릿 초안과 기본(키워드) 답변으로 동작하며 분석에는 영향이 없습니다.
- **질문 응답**: 분석 화면 아래 **결과에 대해 물어보기**에서 질문을 입력하거나 예시 질문을 누릅니다. 키가 있으면 AI가 읽기 전용 도구를 골라 조회한 값으로 답하고("AI 답변", 조회한 도구 표시), 키가 없거나 AI 답변을 쓸 수 없으면 "기본 답변"과 그 이유가 표시됩니다. 답변에는 몇 초에서 20초 정도 걸리고 호출마다 API 비용이 듭니다. 이 대화로 승인·발송은 할 수 없습니다.
- LLM에는 분석이 끝난 수치만 보내고, 문장의 숫자가 입력과 다르면 템플릿으로 대체합니다. 어느 쪽으로 만들었는지는 분석 추적에 `R7:draft:llm` 또는 `R7:draft:template:이유`로 남습니다.

## 4. 허브 데이터 수집 (재현)

`backend/`에서 실행합니다. 결과는 `backend/runtime/`에 저장되며 Git에 올라가지 않습니다.

```bash
# 충전소 목록 수집 → runtime/ev_stations.json (약 35회 호출)
python -m scripts.collect_ev_stations

# 충전 이력(월별·요일별) 수집 → runtime/ev_profile.json
python -m scripts.collect_ev_history                  # 기본: 2021-04, 2022-04
python -m scripts.collect_ev_history 202104 --max-new-months 3

# 충전 이력(일별): 월별 합계와 일치하는지, 날짜별 변동을 확인 (한 달 약 210~250회)
python -m scripts.collect_ev_daily
# 점유율이 더 높아졌다면 EV 용량·위험일 결과가 어떻게 달라지는지 계산
python -m scripts.ev_usage_sensitivity

# 허브 일별 기상으로 기상청 ASOS 교차검증 (ASOS 수집, KPX 수요 파일 필요)
python -m scripts.check_hub_weather <KPX_수요_폴더>
```

- 허브 API에는 **데이터별 일일 호출 한도**가 있습니다. 충전 이력은 한 달에 월별 약 160회 + 요일별 약 80회를 씁니다.
- 받은 달은 `runtime/ev_history_raw/`에 저장되므로 **다시 실행해도 같은 달을 다시 호출하지 않습니다**(호출 0회로 프로필만 다시 만듭니다).
- 한 번에 새로 받는 달은 기본 3개로 제한됩니다(`--max-new-months`로 변경).
- 호출 내역은 `runtime/hub_calls.log`에 남고 실행이 끝나면 이번 실행의 호출 횟수를 출력합니다. 한도가 차면 `403 quota is full`로 멈추고, 받은 달만으로 프로필을 만듭니다.
- 충전소 파일과 이력 프로필이 있으면 배분의 EV 용량이 실측으로 계산됩니다(12시 기준 82.6 → 109.0 MWh). 없으면 가정(출력 7/50 kW, 이용률 50%)을 쓰고, 파일이 아예 없으면 고정 시연값(40 MWh)을 씁니다.

## 5. 모델 학습과 검증 재현 (선택)

모델과 평가는 **대회 제공 데이터가 아니라 공공데이터포털에서 받은 KPX·기상청 자료**로 만듭니다. 원본은 저장소에 없으며 받는 방법과 파일 형식은 `docs/guides/data-acquisition.md`에 있습니다.

```bash
# backend/에서 (xgboost 필요: uv sync --extra ml)
python -m scripts.train_jeju_model ...      # 제주 발전량 모델 → models/jeju
python -m scripts.train_demand_model ...    # 제주 수요 모델   → models/demand
python -m scripts.evaluate_pipeline <KPX_발전량_폴더> <KPX_수요_폴더> runtime/asos <출력제어_zip_또는_폴더>
python -m scripts.allocation_sensitivity    # 저장된 평가 결과로 배분 용량 기준별 비율 재계산(모델 재실행 없음)
```

- 인자와 출력은 `docs/guides/pipeline-evaluation.md`, `docs/guides/jeju-model.md`, `docs/guides/demand-model.md`를 따릅니다.
- `evaluate_pipeline`은 점검 기간(2023-01-01 ~ 2024-05-30)을 학습에서 뺀 모델로 과거 날짜를 판정하고 실제 출력제한일과 비교합니다. 약 30초 걸립니다.

```bash
npm run test:e2e              # 실제 브라우저 흐름 8개와 axe 접근성 검사 (처음 한 번 `npx playwright install chromium` 필요, 포트 5173·8000이 비어 있어야 함)
```

테스트는 외부 네트워크를 호출하지 않습니다(허브·기상청·LLM은 모의 응답).

## 7. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 화면이 "연결 불가" | 백엔드가 실행 중인지(`/health`), 포트 8000을 다른 프로그램이 쓰는지 확인합니다. |
| 로그인이 안 됨 | `backend/.env`의 `APPROVER_TOKEN`을 설정하고 서버를 다시 시작합니다(미설정이면 로그인도 503). 통보문 작성·수정은 로그인 없이 쓸 수 있습니다. |
| `API_TOKEN`을 설정한 뒤 화면이 거부됨 | 화면의 **연결 설정**에 같은 API 키를 입력합니다. |
| `403 Today's quota is full` (허브) | 해당 데이터의 하루 호출 한도가 찼습니다. 다음 날 다시 실행하면 저장된 달은 건너뛰고 이어받습니다. |
| EV 용량이 40 MWh로 고정 | `runtime/ev_stations.json`이 없습니다. 4절의 수집 명령을 실행합니다. |
| live 분석이 시연 값으로 안 바뀌고 실패 | 키 또는 모델 경로가 없습니다. 3절을 확인합니다(의도된 동작). |
| 통보문이 템플릿으로 나옴 | `ANTHROPIC_API_KEY`가 없거나 호출이 실패했거나 숫자 검증에 실패한 경우입니다. 분석 추적의 `R7:draft:template:이유`를 봅니다. |
| `curl`로 data.go.kr 접속이 시간 초과 | 일부 환경에서 `curl`만 막힙니다. Python(httpx) 호출은 정상일 수 있습니다. |
