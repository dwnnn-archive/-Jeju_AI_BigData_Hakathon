## 1. 필수 데이터 (제주데이터허브)

### 1.1 전기자동차 충전소 정보

| 항목 | 내용 |
|---|---|
| 데이터명 | 전기자동차 충전소 정보 (제주데이터허브 데이터 No.494) |
| 출처 | 제주데이터허브 (jejudatahub.net), 제공 형식 API |
| 호출 방식 | `GET https://open.jejudatahub.net/api/proxy/<데이터 키>/<프로젝트 키>?number=&limit=` (limit 최대 100) |
| 인증 | 허브 로그인 → 데이터를 프로젝트에 담기 → 마이페이지 > 프로젝트 관리의 프로젝트 키 |
| 수집 시점 | 2026-11-17, 원본 **3,446행** → 충전 방식별 중복 제거 후 **3,180곳** |
| 데이터 기준일 | 2025-09 (응답의 `baseDate`) |

**사용한 필드**

| 필드 | 의미 | 사용 |
|---|---|---|
| chargingPlace, chargingPlaceDetail | 충전소명, 상세 위치 | 식별·표시 |
| startTime, endTime | 운영 시간 | 시간대별 운영 여부 판정 |
| holiday | 이용 가능 조건 | 입주민·직원 전용, 외부인 제한 제외 |
| chargerCount, quickChargerCount | 완속, 급속 충전기 수 | EV 흡수 용량 계산 |
| latitude, longitude | 위치 | 확장 기능(지도)용 보관 |
| baseDate, provider | 기준일, 제공 기관 | 출처 표시 |

**전처리와 데이터 품질 (실제 확인한 사실)**

1. 운영 시간 표기가 API 가이드의 예시(`00:00`, `23:59`)와 달리 **`0:00`, `24:00:00`** 형태가 대부분(약 3,060곳)이었습니다. 이를 정규화했습니다. `24:00`은 하루의 끝으로 처리합니다.
2. 운영 시간이 `알 수 없음`인 **93곳**은 닫힌 것으로 보수적으로 계산합니다.
3. 이용 조건이 입주민 전용, 직원 전용, 외부인 출입제한 등인 **133곳**은 제외합니다.
4. 자정을 넘기는 운영 시간(예: 22:00~06:00)을 처리합니다.
5. **같은 충전소가 충전 방식별로 여러 행**(예: 완속, 급속, 완속+급속)으로 내려오고 각 행에 충전소 전체 충전기 수가 반복됩니다. 이름·위치·충전기 수가 같은 행을 하나로 합쳤고(266행 제거), 합치지 않으면 충전기 수가 약 8% 부풀려집니다. 이름과 좌표는 같고 상세 위치만 다른 아파트 4곳 등 일부는 남아 있어 약간 높게 잡힐 수 있습니다.
6. 응답에 주소 필드가 없어(가이드 예시에는 있음) 위치는 위도·경도로 표시합니다.

**분석 방법**

- 피크 시각에 운영 중인 충전기 수 × 가정 출력 = 설치 용량(MWh/h)
- **EV 흡수 용량 = 설치 용량 × 이용률 가정(50%)**
- 결과(12시 기준): 운영 충전소 2,969곳, 완속 6,005기, 급속 2,462기, 설치 165.1 MWh/h, 흡수 용량 82.6 MWh
- 충전소별 용량 = 충전기 수 × 가정 출력 × 이용률 가정으로 계산해, 피크 시각에 **여력이 큰 상위 5곳**을 권고에 함께 제시합니다. 이용 패턴 가정은 전체 평균이라 충전소별 혼잡도는 반영하지 못합니다.

| 가정 | 값 | 근거 |
|---|---|---|
| 완속 충전기 출력 | 7 kW | 일반적인 값. 허브 데이터에 출력 정보 없음 |
| 급속 충전기 출력 | 50 kW | 일반적인 값. 허브 데이터에 출력 정보 없음 |
| 남는 전력을 받아 줄 수 있는 비율 | 50% | 실제 이용률 자료 없음. 설정으로 변경 가능 (`EV_IDLE_RATIO`) |

**한계**: 데이터는 정적 목록이라 실시간 사용 여부를 반영하지 못하고, 기준일이 2025-09입니다. 따라서 결과는 **권고안**이며, 앱 화면에도 같은 내용을 표시합니다.

**결과 위치**: 수집본은 `backend/runtime/ev_stations.json`에 저장되며 Git에 올라가지 않습니다. 재생성 명령은 `python -m scripts.collect_ev_stations`.

**이용 조건**: 허브 프로젝트 키를 사용하며, 대회 안내에 따라 제공 파일의 외부 배포·제3자 제공을 하지 않았습니다. 산출물 소유권은 대회 규정을 따릅니다.

### 1.2 일별 기상 정보 · 기상관측소 정보 (교차검증용)

| 항목 | 내용 |
|---|---|
| 데이터명 | 일별 기상 정보 (No.756, API), 기상관측소 정보 (No.757, API) — 제주데이터허브 |
| 호출 방식 | 일별 기상은 `searchDate=YYYYMMDD` 필수로 날짜당 1회, 관측소 정보는 전체 조회. 프로젝트 키는 충전소 API와 같다 |
| 사용 필드 | 관측소명, 일평균 기온(`averageTemperature`), 해발 고도(`seaLevelAltitude`) |
| 수집 | 2024-01-01 ~ 2025-12-31 요청 (731회). 사용 가능 454일 |

**전처리와 데이터 품질**

1. **2025-03-31 이후 9개월은 응답이 비어 있다**("매일 갱신" 표기와 다름). 분석은 2025-03-30까지다.
2. 한라산 고지대 관측소가 섞여 있어(해발 1,665 m 등) 전체 평균은 약 3℃ 낮다. **해발 100 m 미만 17곳**만 평균한다. 값이 있는 관측소가 5곳 미만인 날은 제외한다.
3. ASOS 4곳이 없고, 관측소 정보의 위도·경도 필드가 서로 바뀌어 있어 위치는 쓰지 않았다.

**분석 방법과 결과** (상세: `docs/guides/hub-weather-check.md`, 재현: `python -m scripts.check_hub_weather`)

- 교차검증: 허브 일평균 기온 대 기상청 ASOS 제주(184) 일평균, 454일. 상관 0.996, 편향 −0.51℃, MAE 0.70℃.
- 수요 모델 비교: 2017~2023 학습 모델의 **입력 기온만** 바꿔 검증. 보정 없는 허브 기온은 2024년 MAE 36.5 → 40.4 MW로 나빠지고, 편향 보정(2024에서 구해 2025에 적용)을 하면 2025년 1~3월 89일에서 ASOS와 같은 수준(42.9 대 41.0 MW).

**용도와 한계**: 서비스 입력이나 학습 입력으로 쓰지 않는다(데이터가 끊겼고 2017~2019 학습 구간을 채울 수 없음). 기상청 관측을 독립 출처로 확인하는 교차검증용이다. 검증 구간이 짧아 "허브가 더 낫다"는 주장은 하지 않는다.

## 3. 데이터 흐름

```
[허브 충전소 API] ─▶ 수집 스크립트 ─▶ runtime/ev_stations.json ─┐
[기상청 예보 API] ─▶ 날씨 수집 ─▶ 발전량·수요 모델 ─▶ 위험 판정 ─┴▶ 배분 권고(EV 용량) ─▶ 담당자 승인
[KPX 이력 파일]  ─▶ 모델 학습(오프라인)
[허브 일별 기상] ─▶ 기상청 ASOS 교차검증, 수요 모델 입력 비교(오프라인, 서비스 입력 아님)
```

## 4. 외부 데이터·오픈소스 목록

**외부 데이터**: 위 2절의 KPX, 기상청 자료.

**오픈소스** (정확한 버전은 `backend/pyproject.toml`, `backend/uv.lock`, `frontend/package.json` 참조)

| 구분 | 라이브러리 |
|---|---|
| 백엔드 | FastAPI, Uvicorn, Pydantic / pydantic-settings, LangGraph, langgraph-checkpoint-sqlite, httpx, filelock |
| 모델(선택 설치) | XGBoost, NumPy |
| 프런트 | React, TypeScript, Vite, zod, lucide-react |
| 테스트 | pytest, Vitest, Playwright |

LLM(Anthropic Claude)은 **통보문 초안 문장 작성에만** 선택적으로 사용합니다. LLM에는 분석이 끝난 수치(위험등급, 잉여전력, 배분량 등)만 보내며 허브 원본 데이터와 충전소 이름은 보내지 않습니다. 키가 없으면 템플릿 초안을 씁니다.

## 5. 재현 방법

```bash
cd backend
uv sync --frozen --extra dev --extra ml
cp .env.example .env     # JEJUHUB_PROJECT_KEY, KMA_API_KEY 등 입력
python -m scripts.collect_ev_stations   # 허브 충전소 수집
python -m pytest -q                      # 백엔드 테스트
python -m scripts.check_hub_weather <KPX_수요_폴더>   # 허브 일별 기상 교차검증(ASOS 수집 선행)
```

**주의**: 키는 `.env`에만 두며 저장소에 올리지 않습니다.
