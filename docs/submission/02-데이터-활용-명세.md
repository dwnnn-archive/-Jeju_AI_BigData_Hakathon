**사용한 필드**

| 필드 | 의미 | 사용 |
|---|---|---|
| chargingPlace, chargingPlaceDetail | 충전소명, 상세 위치 | 식별·표시 |
| startTime, endTime | 운영 시간 | 시간대별 운영 여부 판정 |
| holiday | 이용 가능 조건 | 입주민·직원 전용, 외부인 제한 제외 |
| chargerCount, quickChargerCount | 완속, 급속 충전기 수 | EV 흡수 용량 계산 |
| latitude, longitude | 위치 | 확장 기능(지도)용 보관 |
| baseDate, provider | 기준일, 제공 기관 | 출처 표시 |

**전처리와 데이터 품질 (실제 확인한 사실)**

1. 운영 시간 표기가 API 가이드의 예시(`00:00`, `23:59`)와 달리 **`0:00`, `24:00:00`** 형태가 대부분(약 3,060곳)이었습니다. 이를 정규화했습니다. `24:00`은 하루의 끝으로 처리합니다.
2. 운영 시간이 `알 수 없음`인 **93곳**은 닫힌 것으로 보수적으로 계산합니다.
3. 이용 조건이 입주민 전용, 직원 전용, 외부인 출입제한 등인 **133곳**은 제외합니다.
4. 자정을 넘기는 운영 시간(예: 22:00~06:00)을 처리합니다.
5. **같은 충전소가 충전 방식별로 여러 행**(예: 완속, 급속, 완속+급속)으로 내려오고 각 행에 충전소 전체 충전기 수가 반복됩니다. 이름·위치·충전기 수가 같은 행을 하나로 합쳤고(266행 제거), 합치지 않으면 충전기 수가 약 8% 부풀려집니다. 이름과 좌표는 같고 상세 위치만 다른 아파트 4곳 등 일부는 남아 있어 약간 높게 잡힐 수 있습니다.
6. 응답에 주소 필드가 없어(가이드 예시에는 있음) 위치는 위도·경도로 표시합니다.

**분석 방법**

- 피크 시각에 운영 중인 충전기 수 × 가정 출력 = 설치 용량(MWh/h)
- **EV 흡수 용량 = 설치 용량 × 이용률 가정(50%)**
- 결과(12시 기준, 가정 적용): 운영 충전소 2,969곳, 완속 6,005기, 급속 2,462기, 설치 165.1 MWh/h, 흡수 용량 82.6 MWh
- **충전 이력 프로필을 반영하면**(1.3절) 같은 시각의 설치 용량 126.1 MWh/h, 흡수 용량 **109.0 MWh**입니다. 실측 평균 전력이 가정보다 낮아 설치 용량은 줄지만, 실측 점유율이 낮아(12시 완속 15.8%, 급속 12.1%) 여유 비율이 가정 50%보다 커집니다.
- 충전소별 용량 = 충전기 수 × 가정 출력 × 이용률 가정으로 계산해, 피크 시각에 **여력이 큰 상위 5곳**을 권고에 함께 제시합니다. 이용 패턴 가정은 전체 평균이라 충전소별 혼잡도는 반영하지 못합니다.

| 가정 | 값 | 근거 |
|---|---|---|
| 완속 충전기 출력 | 7 kW | 일반적인 값. 허브 데이터에 출력 정보 없음 |
| 급속 충전기 출력 | 50 kW | 일반적인 값. 허브 데이터에 출력 정보 없음 |
| 남는 전력을 받아 줄 수 있는 비율 | 50% | 실제 이용률 자료 없음. 설정으로 변경 가능 (`EV_IDLE_RATIO`) |

**한계**: 데이터는 정적 목록이라 실시간 사용 여부를 반영하지 못하고, 기준일이 2025-09입니다. 따라서 결과는 **권고안**이며, 앱 화면에도 같은 내용을 표시합니다.

**결과 위치**: 수집본은 `backend/runtime/ev_stations.json`에 저장되며 Git에 올라가지 않습니다. 재생성 명령은 `python -m scripts.collect_ev_stations`.

**이용 조건**: 허브 프로젝트 키를 사용하며, 대회 안내에 따라 제공 파일의 외부 배포·제3자 제공을 하지 않았습니다. 산출물 소유권은 대회 규정을 따릅니다.

**용도와 한계**: 서비스 입력이나 학습 입력으로 쓰지 않는다(데이터가 끊겼고 2017~2019 학습 구간을 채울 수 없음). 기상청 관측을 독립 출처로 확인하는 교차검증용이다. 검증 구간이 짧아 "허브가 더 낫다"는 주장은 하지 않는다.

### 1.3 전기자동차 충전 이력 (월별·요일별)

| 항목 | 내용 |
|---|---|
| 데이터명 | 전기자동차 충전 이력 월별·요일별 (제주데이터허브, 운영기관은 데이터상 환경부) |
| 수집 | 2021-04, 2022-04 두 달. 월별 14,277행 + 17,134행, 요일별 7,188행 + 8,708행. 호출 약 475회(승인받은 추가 쿼터 사용) |
| 사용 필드 | 충전기·충전소 ID, 충전기 종류, 충전 시작 시각(월별), 요일(요일별), 충전 횟수·시간·충전량 |
| 일별 이력 | 시간·요일 정보가 없어 쓰지 않음(호출하지 않음) |

**분석 방법**
- 충전기가 낸 평균 전력 = 충전량 ÷ 충전 시간. 완속 6.0 kW, 급속 36.7 kW(가정 7/50 kW 대체).
- 시간대별 점유율 = 충전 중인 시간 ÷ 충전기 가용 시간. 충전 시작 시각만 알고 끝 시각은 모르므로, 평균 충전 시간만큼 뒤 시간으로 이어 나눕니다. 12시 기준 완속 15.8%, 급속 12.1%(최대 19.6%, 12.7%).
- 요일 보정: 월 1.02, 화 1.02, 수 1.03, 목 1.03, 금 1.07, 토 0.93, 일 0.90.
- 이용률 가정 50%를 이 점유율의 여집합(여유 비율 완속 84%, 급속 88%)으로 대체합니다.

**데이터 품질**
- `evChargerId`는 충전소 안의 번호(1, 2, ...)라 이것만으로 충전기를 세면 25기로 잘못 셉니다. (충전소 ID, 충전기 ID) 쌍으로 구분하며, 2021-04에 충전기 742기(충전소 422곳), 2022-04에 841기(477곳)입니다. 이 보정 전에는 점유율이 100%로 잘려 나왔습니다.
- 충전기 종류가 비어 있거나 시간 형식이 맞지 않은 4행은 제외했습니다.

**한계**
- 이력은 **2021-04, 2022-04의 과거 자료**입니다. 이후 전기차 보급이 늘었다면 오늘의 점유율은 더 높고, 여유 용량은 더 작을 수 있습니다.
- 이력에 나오는 충전소(422~477곳)는 허브 충전소 정보(3,180곳)의 일부입니다.
- 점유율을 전체 평균으로 쓰며 충전소별 혼잡도는 반영하지 못합니다. 이력에 한 번도 나오지 않은 충전기는 분모에서 빠져 점유율을 높게 잡습니다.
- 달은 봄 두 달만 받아 계절 대표성이 약합니다.

### 2.1 ESS 계량데이터와 설비 현황에서 확인한 것

**제주 ESS 계량데이터** (시간별 충전량·발전량(방전), MWh)
- 총 충전 55,674 MWh, 총 방전 49,030 MWh (방전÷충전 88.1%).
- 시간당 충전은 최대 37.7 MWh(2025-12-30 12시), 상위 1% 18.3 MWh입니다. 낮 10~13시와 밤 0~3시에 충전하고 저녁 18~21시에 방전합니다.
- 제어 이력이 있는 2024-01-01 ~ 05-30에서 출력제한이 걸린 234시간(53일)의 09~15시 평균 충전은 8.86 MWh로, 제한 없던 시간(5.67)보다 높았습니다. 다만 최대 20.9 MWh에 머물러 한계까지 흡수하지는 못했습니다.
- 이 계량값이 제주의 어느 ESS까지 포함하는지는 데이터 설명에 없어 확인하지 못했습니다. 설비 용량이 아니라 **실적**이므로 용량의 하한입니다.
- 이전 BESS 시연값(70 MWh, 피크 1시간)은 이 관측 최대(37.7)의 약 1.9배였습니다. **BESS 용량을 관측 최대인 37.7 MWh로 교체했습니다.** 실적이 용량의 하한이므로 실제 용량은 이보다 클 수 있어, 보수적인 값입니다. 이에 따라(P2X 교체 포함) 위험일 시연의 흡수는 EV 고정값(40 MWh) 기준 111.0 MWh(48.3%), 충전 이력 반영 시 180.0 MWh(78.3%, 잔여 50.0 MWh)입니다.

**P2X(수소 전환) 용량** (언론 보도)
- 제주 행원 그린수소 실증단지의 수전해 설비는 3.3 MW급이고 설계상 하루 최대 600kg, 현재 하루 약 200kg을 생산한다고 보도됐습니다([파이낸셜뉴스](https://www.fnnews.com/news/202609160938502575), [뉴스토마토](https://newstomato.com/ReadNews.aspx?no=1313951), 모두 2026-09-16). 3.3 MW와 약 200kg은 두 곳에서 일치합니다.
- 이전 시연값 P2X 30 MWh는 이 설비 규모의 약 9배였습니다. **P2X 용량을 3.3 MWh(피크 1시간 풀가동 상한)로 교체했습니다.** 50 MW급 실증은 예비타당성조사 대상일 뿐 아직 없는 설비입니다.
- 수소 환산 13 kg/MWh는 가정으로 유지합니다. 보도 기준 범위는 약 7.6(설계 하루 600kg ÷ 3.3 MW × 24시간, 본 문서의 계산)에서 18([1 MW PEM 시간당 18kg](https://www.ceoscoredaily.com/page/view/2024072617575935265), 2024-07-26)입니다.
- 한계: 공식 통계가 아닌 보도 수치이고, 행원 외의 소규모 설비는 포함하지 않았습니다. **VPP 30 MWh는 제주 공개 통계를 찾지 못해 시연 추정치로 유지합니다.**

**제주 신재생에너지 발전시설 현황** (기준일 2024-12-31)
- 태양광 1,653건 553.75 MW(모두 3MW 미만), 풍력 25건 374.89 MW, 바이오가스·수력 약 5.5 MW. 합계 934.2 MW.
- ESS·수소·연료전지 항목은 없습니다(`원동력종류`는 태양광, 풍력, 바이오가스, 수력, 소수력).
- 태양광 누적 설비는 2016년 93 MW에서 2024년 554 MW로 약 6배가 됐고, 2024년에 풍력이 104.2 MW 늘었습니다(한림해상풍력 100 MW 포함).
- 한계: 2025년 신규 설비가 빠져 있고, 태양광이 모두 3MW 미만이라 제주 전체 설비라고 단정할 수 없습니다.

**설비값과 시연 결과의 관계**
- 설비 용량은 **live 모드의 모델 없는 물리 추정 폴백**에만 쓰이며, 이전의 근거 없는 시연값(풍력 900 MW, 태양광 600 MW)을 위 실제 합계(풍력 374.89 MW, 태양광 553.75 MW)로 바꿨습니다.
- **시연 모드의 발전량은 시나리오 파일의 고정값이라 설비 용량과 무관합니다.** 따라서 시연 결과(위험일 잉여 230.0 MWh 등)는 이번 교체로 달라지지 않았습니다.
- 모델 없이 계산한 물리 추정은 설비값이 실제여도 미검증 추정이므로 계속 "시연(추정)"으로 표시하고 승인·발송을 막습니다.

## 3. 데이터 흐름

```
[허브 충전소 API]   ─▶ 수집 스크립트 ─▶ runtime/ev_stations.json ─┐
[허브 충전 이력 API] ─▶ 수집 스크립트 ─▶ runtime/ev_profile.json ──┤ (평균 전력·점유율·요일 보정)
[기상청 예보 API]   ─▶ 날씨 수집 ─▶ 발전량·수요 모델 ─▶ 위험 판정 ──┴▶ 배분 권고(EV 용량) ─▶ 담당자 승인 ─▶ 통보문
[KPX 이력 파일]     ─▶ 모델 학습(오프라인)                                           ▲
[KPX ESS 계량·설비 현황] ─▶ BESS·설비 용량 산정                       LLM은 통보문 문장만(숫자는 코드가 검증)
[허브 일별 기상]    ─▶ 기상청 ASOS 교차검증, 수요 모델 입력 비교(오프라인, 서비스 입력 아님)
```

## 4. 외부 데이터·오픈소스 목록

**외부 데이터**: 위 2절의 KPX, 기상청, 제주특별자치도 자료와 언론 보도(P2X 용량 근거). 전체 목록은 활용 데이터 표(별도 정리)를 따릅니다.

**오픈소스** (정확한 버전은 `backend/pyproject.toml`, `backend/uv.lock`, `frontend/package.json` 참조)

| 구분 | 라이브러리 |
|---|---|
| 백엔드 | FastAPI, Uvicorn, Pydantic / pydantic-settings, LangGraph, langgraph-checkpoint-sqlite, httpx, filelock |
| 모델(선택 설치) | XGBoost, NumPy |
| 프런트 | React, TypeScript, Vite, zod, lucide-react |
| 테스트 | pytest, Vitest, Playwright |

LLM(Anthropic Claude)은 **통보문 초안 문장 작성에만** 선택적으로 사용합니다. LLM에는 분석이 끝난 수치(위험등급, 잉여전력, 배분량 등)만 보내며 허브 원본 데이터와 충전소 이름은 보내지 않습니다. 키가 없으면 템플릿 초안을 씁니다.

## 5. 재현 방법

```bash
cd backend
uv sync --frozen --extra dev --extra ml          # LLM 초안을 쓰려면 --extra llm 추가
cp .env.example .env     # JEJUHUB_PROJECT_KEY, KMA_API_KEY 등 입력
python -m scripts.collect_ev_stations   # 허브 충전소 수집 (약 35회 호출)
python -m scripts.collect_ev_history    # 허브 충전 이력 수집 (월별·요일별 2개월, 약 475회) → ev_profile.json
python -m scripts.allocation_sensitivity # 배분 용량 기준별 비율 재계산(저장된 평가 결과 필요)
python -m pytest -q                      # 백엔드 테스트
python -m scripts.check_hub_weather <KPX_수요_폴더>   # 허브 일별 기상 교차검증(ASOS 수집 선행)
```

**주의**: 키는 `.env`에만 두며 저장소에 올리지 않습니다.
