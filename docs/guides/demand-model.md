# 제주 수요 예측 모델

하루 전 제주 시간별 전력수요(MWh)를 예측한다. 서비스의 수요는 지금 시연값(500 MWh)이라서, 이 모델이 `KPX_URL`(중계)이 없을 때 live 수요를 대신한다. 데이터는 [demand-options.md](demand-options.md), 발전량 모델은 [jeju-model.md](jeju-model.md) 참고.

## 구조

| 항목 | 내용 |
|---|---|
| 정답 | KPX 제주 실측 수요(발전단 수요, MWh) |
| 입력 | 시각, 요일, 공휴일, 전날·다음날 휴일 여부, 월, 연중 일, **하루 평균 기온**, 연도 추세 |
| 입력에 **없는 것** | 최근 실측 수요(어제 같은 시각 수요 등). 서비스에 실측 수요를 받는 경로가 없다 |
| 기온 | 학습은 ASOS 제주(184) 실측, 서비스는 제주시 예보 격자(53,38) |
| 학습 | 2017-01-01 ~ 2023-12-31 (61,339행) |
| 검증 | 2024-01-01 ~ 2025-12-31 (17,543행, 시간순 홀드아웃). 2026년은 기온 수집이 2025-12까지라 제외 |
| 공휴일 | 대체·임시공휴일 포함 2007~2030 표(`app/domain/kr_holidays.py`). 2031년 이후는 주말만 쉬는 날로 본다 |
| 저장 모델 | `--refit-all`을 주면 2017 ~ 2025 전체로 다시 학습해 저장(보고 지표는 홀드아웃 값 그대로) |

시간별 기온과 하루 최고·최저 기온은 일부러 쓰지 않는다. 아래 "설계 선택" 참고.

## 실행

```bash
cd backend
# 선행: ASOS 수집(collect_asos), KPX 수요 파일(data.go.kr, 한 폴더), KPX PSS 엑셀(비교용, 같은 폴더 가능)
python -m scripts.train_demand_model <KPX_수요_폴더> runtime/asos runtime/models/demand \
    --pss-dir <PSS_엑셀_폴더> --refit-all
# 서비스에서 사용: backend/.env 에 설정 (live 모드, KMA_API_KEY 필요, KPX_URL 은 비워 둠)
#    JEJU_DEMAND_MODEL_DIR=runtime/models/demand
```

학습은 약 15초. 모델 파일은 `runtime/`에 만들어져 Git에 올라가지 않는다. `meta.json`에 검증 지표가 있다. `KPX_URL`(KPX 공식 예측을 중계하는 서버)을 설정하면 그쪽이 우선하고, 둘 다 없으면 시연값이 아니라 **명시적 실패**(`ALLOW_MOCK_FALLBACK`을 켠 경우에만 시연값)다. 결과의 `validated`는 계속 `False`라서 승인·발송 차단은 그대로다.

## 검증 결과 (2026-11-16, 검증 2024~2025, 실측 수요 대비)

| | MAE | MAPE | 편향 | R² | 하루 최대값 MAE |
|---|---|---|---|---|---|
| **우리 모델 (실측 기온 사용)** | 36.5 MW | 5.06% | −0.2 | 0.874 | **30.0** |
| KPX 하루전 예측 | 36.3 MW | 4.95% | −15.0 | 0.876 | 35.1 |
| 월 × 요일유형 × 시각 평균 | 78.1 MW | 9.98% | −68.7 | 0.440 | 96.8 |

- 2024년 MAE 36.5(KPX 36.4), 2025년 36.5(KPX 36.1)로 연도별로도 KPX와 같은 수준이다.
- 평균 기준선 대비 오차가 절반 이하다. 기여도는 하루 평균 기온 30%, 시각 24%, 월 12%, 연도 추세 12%, 연중 일 8%, 공휴일 7%.
- **우리 모델은 편향이 거의 없고(−0.2) 하루 최대값 오차가 작다(30.0 대 35.1).** KPX 예측은 늘 15 MW쯤 낮게 예측한다. 위험 판단에는 하루 최대 수요가 중요해서 이 점이 유리하다.

### 예보 기온 오차를 넣으면 (중요)
위 표는 **실측 기온**을 썼다. 서비스는 예보 기온을 쓰므로 실제 성능은 더 낮다. 실제 예보 오차는 측정하지 못해서(과거 예보 이력이 없다) 오차를 가정해 섞어 보았다.

| 가정한 기온 오차 | 우리 모델 MAE | KPX MAE |
|---|---|---|
| 없음 (실측) | 36.5 | 36.3 |
| 하루 단위 치우침 1.5℃ + 매시간 1.0℃ (약) | **39.8** | 36.3 |
| 하루 단위 치우침 2.5℃ + 매시간 1.5℃ (강) | **44.6** | 36.3 |

- **예보 기온이 정확하면 KPX와 같고, 현실적인 오차에서는 KPX보다 10~23% 나쁘다.** KPX 예측은 최근 실측 수요 등을 쓸 수 있어 우리보다 유리한 조건이다.
- 그래서 KPX 공식 예측을 받을 수 있게 되면(중계 `KPX_URL`) 그쪽을 우선하고, 이 모델은 자동 대체로 쓰는 것이 맞다.

## 설계 선택 (시험한 것)

같은 검증 구간에서 기온 입력을 바꿔 보았다(MAE, MW).

| 모델 변형 | 실측 기온 | 오차 약 | 오차 강 |
|---|---|---|---|
| 시간별 + 하루 평균·최고·최저 기온 | **34.0** | 41.3 | 48.6 |
| **하루 평균 기온만 (채택)** | 36.5 | **39.8** | **44.6** |
| 하루 평균·최고 | 36.2 | 40.4 | 45.6 |

- 실측 기온에서는 기온을 많이 쓸수록 정확하지만 예보 오차에 훨씬 민감하다. **서비스는 예보를 쓰므로 오차에 강한 "하루 평균 기온만" 안을 채택했다.**
- 학습 기온에 오차를 섞는 방법(데이터 3배 증강)도 시험했지만 **오히려 크게 나빠졌다**(실측 기온에서도 MAE 47~50). 채택하지 않았다.

## 한계

- 검증은 실측 기온이다. 실제 예보 기온 오차는 측정하지 못했다(과거 예보 이력이 없다). **서비스에서 예보를 저장해 두면 이후 실제 오차로 다시 평가할 수 있다.**
- KPX 예측과의 비교는 조건이 다르다(KPX는 최근 수요를 쓸 수 있고 우리는 쓰지 않는다).
- 2026년은 검증하지 않았다(기온 수집이 2025-12까지). 최근 구조 변화(전기차, 태양광 증가)에 따른 추세는 연도 추세 하나로만 반영한다.
- 수요 값에 "시장 참여 태양광 포함"의 정확한 의미는 KPX에 확인하지 못했다.
- 공휴일 표는 `holidays` 패키지(0.108) 기준이며 2031년 이후는 없다.
- 위험 규칙은 이 모델과 별개로 바꿨다. 이전 규칙(`발전량 − 수요`, 150/200 MWh)은 실제 수요에서 출력제한을 잡지 못해 발전량 ÷ 수요 비율 규칙으로 교체했고, 수요 출처(KPX 예측, 이 모델)에 따른 탐지 성능 비교는 [demand-options.md](demand-options.md)에 있다.
