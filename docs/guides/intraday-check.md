# 당일 점검 (초단기예보) — 시험 브랜치 `안봄-초단기예보`

하루 전 계획(단기예보)이 "정상"인 날만 당일에 초단기실황·초단기예보로 다시 점검하는 기능이다. 하루 전 판정이 위험이면 거기서 끝내므로 **놓침만 줄이는 구조**다. 근거는 [pipeline-evaluation.md](pipeline-evaluation.md)의 시뮬레이션(포착 81~83% → 약 93%, 오경보 +14~39일).

이 브랜치는 `안봄` 위에서 실험하는 시험 브랜치다. 기술 검증이 끝나지 않거나 팀이 당일 점검을 하지 않기로 하면 브랜치만 지우면 된다.

## 성공 기준 (기술 검증)

| 기준 | 상태 |
|---|---|
| 1. 실제 키로 초단기 API 호출, 풍속·기온·하늘상태 파싱 | **완료** (실제 호출로 확인) |
| 2. 실측·초단기예보·하루 전 예보를 이어 붙인 입력으로 판정이 동작 | **완료** (오늘 날짜로 실제 점검 실행, 출력값이 상식적) |
| 3. 당일 점검 결과를 이력으로 남기고 화면에 표시 | **미착수** (`inputs`에 기록할 값은 반환하지만 저장·표시는 아직 없음) |
| 실제 정확도 이득 | **지금은 측정 불가.** 기상청이 과거 예보를 3일치만 줘서 예보를 저장해 쌓아야 확인할 수 있다 |

## 확인한 사실 (가이드 + 실제 호출)

- 초단기실황(`getUltraSrtNcst`)은 매시 정각 자료(10분 뒤부터), 풍속 `WSD`·기온 `T1H`가 있고 **하늘상태는 없다.** 현재 정시 한 시점뿐이라 같은 날 지난 시간의 실측 이력은 이 API로 얻을 수 없다.
- 초단기예보(`getUltraSrtFcst`)는 매시 30분 생성, 45분 뒤부터 제공, **기준 시각의 다음 정시부터 6시간**이다(기준 20:30 → 21:00~02:00). 시각은 단기예보처럼 `fcstTime HH00 → HH시`로 읽는다.
- **초단기예보의 풍속·기온은 정수로 온다**(`WSD 3, 4, 5`). 단기예보보다 거칠다.
- 같은 키·같은 주소(공공데이터포털)로 단기예보와 함께 동작한다.
- **기상청은 최근 3일 치 발표분만 다시 준다**(`최근 3일 간의 자료만 제공합니다`). 그래서 당일 점검의 하루 전 입력은 전날 23시 발표분을 그때그때 다시 받아 쓰면 되지만(저장 불필요), **예보 정확도를 평가하려면 예보를 저장해 두는 것이 유일한 방법**이다.

## 동작

`ToolBundle.intraday_check(request, now)` (`app/tools/bundle.py`)

1. 하루 전 입력: 전날 23시 발표 단기예보를 다시 받는다(고산 격자는 발전량 모델용, 제주시 격자는 수요 모델용).
2. 초단기실황과 초단기예보를 두 격자에서 받는다.
3. `blend_weather`(`app/tools/intraday.py`)로 하루 24시간을 이어 붙인다.

| 시간 | 쓰는 값 |
|---|---|
| 점검 시각 이전 | 하루 전 예보 (이미 지난 시간, 판정에서도 제외) |
| 점검 시각(현재 정시) | 초단기실황의 풍속·기온, 하늘상태는 초단기예보 또는 하루 전 예보 |
| 이후 6시간 | 초단기예보 (풍속·기온·하늘상태) |
| 그 뒤 | 하루 전 예보 |

4. 발전량 모델과 수요 모델로 예측하고 `rules.evaluate(..., from_hour=지금 시각)`로 판정한다. **지금 시각 이후**의 시간만 피크와 등급에 쓴다. 표에는 24시간이 모두 남는다.

모델·키·입력이 하나라도 없으면 시연값 등으로 조용히 대체하지 않고 예외를 낸다. 반환값의 `inputs`(하루 전 발표분, 시간별 출처, 이어 붙인 날씨)는 나중에 저장해서 정확도 평가에 쓰도록 남긴 것이다.

## 한계와 다음 단계

- **아직 서비스 흐름(LangGraph, 작업 큐, 화면)에 연결하지 않았다.** `intraday_check`는 호출 가능한 부품이다.
- **정해진 시각에 실행하는 장치가 없다**(작업 큐만 있다). 앱 내부 스케줄러와 외부 스케줄러 중 팀 결정이 필요하다.
- 점검 시각(07:45, 10:45)은 출력제한 피크(9~15시) 3~6시간 전이다. 그 시간에 담당자 승인과 설비 대응이 가능한지는 확인하지 못했다.
- 시뮬레이션의 93%는 초단기예보 오차를 가정한 값이다. 실제 이득은 예보를 저장해 쌓은 뒤에야 확인된다.
- 다음: (1) 점검 결과와 입력 기록의 저장, (2) 판정 이력 표시, (3) 하루 전 결과가 NORMAL일 때 최대 2회 점검하는 그래프 연결, (4) 스케줄링.
