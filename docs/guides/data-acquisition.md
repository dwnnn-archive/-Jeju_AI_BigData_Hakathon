## 1. 제주 풍력·태양광 발전량 (학습 정답값)

**한국전력거래소_지역별 시간별 태양광 및 풍력 발전량** ([data.go.kr/15065269](https://www.data.go.kr/data/15065269/fileData.do)) — 확인됨
- 열: 거래일, 거래시간, 지역, 연료원, 전력거래량(MWh). CSV, 이용허락 제한 없음, 무료. 수정일 2026-04-21, 연간 갱신, 2025년도 포함.
- 풍력은 육지/제주 구분, 태양광은 시도별입니다. 파일을 받아 확인한 결과 **태양광에도 제주(`제주도`)가 포함**됩니다.
- 전력시장 참여 발전기의 **송전단 기준**이라 자가용·소규모는 빠집니다. 수정정산으로 값이 바뀔 수 있고, **ESS 충방전량이 섞여 있습니다.**
- 주기성 과거 파일 9개가 있어 2013-01 ~ 2025-12 전 기간을 받을 수 있습니다(풍력은 2017-01부터).

이 데이터는 `generation_mwh` 라벨이 **제주 전체 풍력, 제주 전체 태양광 합계** 단위로 나온다는 뜻입니다. 현재 저장소는 설비별 레지스트리(`plants.json`)로 계산하므로, 학습 모델은 단지 단위가 아니라 **제주 전체 단위**로 설계하는 편이 데이터에 맞습니다. 또한 시장 참여분만 잡혀 실제 발전량보다 작을 수 있어 "출력제한 전 잠재 발전량"과는 구분해야 합니다.

**제주에너지공사_풍력발전기 전력 정보** ([data.go.kr/15028181](https://www.data.go.kr/data/15028181/fileData.do)) — 확인됨
- 5개 단지(가시리, 김녕리, 동복리, 신창리, 행원리)의 **일 평균** 발전량. 2016-10-01부터, 분기 갱신, CSV, 무료. 단위 미표기.
- 시간별이 아니므로 학습 라벨로는 부적합하고, 단지별 비중 파악 정도로 씁니다. 태양광 5개 단지 데이터도 별도로 있는 것으로 검색됩니다(미확인).

## 2. 과거 실측 기상 (학습 입력)

단기예보 API는 **과거 값을 주지 않으므로** 학습용은 관측 자료가 필요합니다.

**기상청_지상(종관, ASOS) 시간자료 조회서비스** ([data.go.kr/15057210](https://www.data.go.kr/data/15057210/openapi.do)) — 확인됨
- 엔드포인트 `https://apis.data.go.kr/1360000/AsosHourlyInfoService`
- 필수 파라미터: `ServiceKey`, `dataCd=ASOS`, `dateCd=HR`, `startDt`, `startHh`, `endDt`, `endHh`, `stnIds`. 종료일은 전일(D-1)까지.
- 응답: 기온 `ta`, **일사 `icsr`**, 일조 `ss`, 풍속 `ws`, 풍향 `wd`, 습도 `hm`, 전운량 `dc10Tca` 등. 지점별 시작 시점이 다르고 최대 1904년부터.
- 미확인: 일사량 단위(MJ/m² 추정이나 문서에 없음), 일일 호출 한도, **제주 지점번호**(활용가이드 하단 목록 참조). 제주 지점은 제주·고산·성산·서귀포 등이 있는 것으로 알고 있으나 번호는 가이드로 확인이 필요합니다.
- 기상청 단기예보와 같은 **공공데이터포털 계정**으로 활용신청하면 됩니다. 단, 기존 단기예보 키가 이 서비스에도 자동 적용되지 않으므로 서비스별로 신청해야 합니다.

일사량 단위가 W/m²가 아니면 학습 CSV 스키마(`irradiance_wm2`)로 변환이 필요합니다.

## 3. 제주 전력 수요

**한국전력거래소_시간별 전국 전력수요량** ([data.go.kr/15065266](https://www.data.go.kr/data/15065266/fileData.do)) — 확인됨
- 날짜 × 1~24시, MWh, CSV. 발전단 수요이며 **수요예측용 잠정자료**. 수정일 2026-02-23, 연간 갱신.
- **육지와 제주를 합산한 전국 값**이고 제주 분리 정보가 없습니다.

제주 단독 시간별 수요·하루전 수요예측 데이터셋은 검색으로 **찾지 못했습니다.** 기획서의 Tool 3(제주 하루전 수요)이 가장 위험한 지점입니다. 선택지는 다음과 같습니다.

1. KPX 전력통계정보시스템(EPSIS)·제주본부 등에서 제주 계통 수요 자료가 있는지 직접 확인(미확인).
2. 제주 수요를 전국 수요에서 비율로 추정(정확도 검증 불가, 문서에 "추정"으로 명시 필요).
3. 시연 수요(fixture)를 유지하고 발표에서 한계로 밝히기. 현재 저장소의 KPX 어댑터는 사용자 관리 중계 서버 계약이라 데이터가 확보되면 그대로 붙일 수 있습니다.

## 4. 출력제한 이력 (검증·평가용)

공공데이터포털의 직접적인 "출력제어" 데이터셋은 **찾지 못했습니다.** 한 블로그([해줌](https://blog.haezoom.com/insight_vpp_48/))가 KPX가 공공데이터포털에 공개한 자료로 일수를 집계했다고 하므로 존재 가능성은 있으나 원본은 미확인입니다. 보도 기준 제주 태양광 출력제어는 2021년 1회, 2022년 28회, 2023년 64회, 2024년 보도에서 지난해 120여 차례로 집계 기준이 달라 직접 비교는 어렵습니다. data.go.kr에서 "출력제어"로 직접 검색해 보세요.

## 모델링 방향: 제주 전체 단위 (확정)

학습 정답(KPX)이 제주 전체 합계로만 시간별 제공되고 설비 용량 레지스트리도 비어 있어, 단지별이 아니라 **제주 전체 단위 모델**로 간다.

- **정답**: KPX 제주 풍력 시간별 발전량(MWh). 태양광은 제주가 분리되는지 확인 후 결정하며, 분리되지 않으면 이번 모델은 풍력 중심으로 한다.
- **입력(학습)**: ASOS 제주권 여러 지점의 풍속·기온·일사량. 평균 또는 지점별 열.
- **입력(추론)**: 단기예보를 같은 지점의 격자로 받아 학습과 같은 형태로 맞춘다(한림 48,36 / 제주 53,38 / 조천 55,39 / 구좌 59,38 등).
- **계산**: 기존 "설비 용량 × 출력 곡선"은 보조로 두고 XGBoost가 제주 전체 발전량을 직접 예측한다.
- **표현 주의**: KPX 값은 시장 참여 발전기만 잡히고 ESS가 섞여 있다. "실제 발전량"이 아니라 **"시장 거래된 발전량" 예측**으로 문서·발표에서 구분한다.
- **미결**: 출력제한이 걸린 시간대의 발전량은 억제된 값일 수 있어 학습에서 처리 방식을 정해야 한다.
- **코드 영향**: `tool2_predict_generation.py`, `scripts/train_model.py`, 학습 CSV 스키마(`wind_capacity_mw`, `solar_capacity_mw`)와 관련 테스트가 바뀐다. 실제 CSV 구조를 확인한 뒤 수정한다.

## 분석 결과: KPX 발전량 파일 (2026-11-16)

받은 파일 10개(2013-01 ~ 2025-12)를 제주 시간별로 정규화해 검증했다. 정규화 코드는 `backend/scripts/kpx_generation.py`, 테스트는 `backend/tests/test_kpx_generation.py`.

```bash
cd backend
python -m scripts.kpx_generation <KPX_CSV_폴더> <출력.csv>   # timestamp, wind_mwh, solar_mwh, wind_usable
```

**파일 형식이 서로 다르다.** 코드가 아래를 흡수한다.

| 차이 | 내용 |
|---|---|
| 구조 | 연료원 열이 있는 long(2023-12, 2024, 2025), 태양광·풍력 열이 나란한 wide(2017~2023), 태양광 전용(2013~2021) |
| 시간 | `시간` 열은 0~23(시작 시각), `거래시간` 열은 1~24(종료 시각). 1을 빼서 맞춤. 겹침 구간 상관 1.0000으로 검증 |
| 단위 | 20211231 파일의 `발전량`만 **kWh**(다른 파일의 정확히 1000배). 1000으로 나눔 |
| 지역명 | `제주도`와 `제주`가 섞여 있고 같은 대상 |
| 인코딩 | 전부 CP949 |
| 빈 값 | 공백 문자열. 2017~2019 풍력에 약 1% |

**검증**
- 제주 시계열 113,952시간(2013~2025)이 빈 구간 없이 만들어진다. 20201231 파일의 755시간 누락은 20230228 파일이 보완한다.
- 겹치는 기간의 파일끼리 값이 일치한다(20211231은 ÷1000 후).
- 제주 전용 파일(`제주지역 태양광_풍력 시간대별 발전량_20231231`, 2019-12~2023-12)과 비교하면 풍력 상관 0.995(합계 비 1.006), 태양광 0.999(0.977). 같은 제주 발전량을 다른 정산으로 집계한 값으로 보이며 서로를 뒷받침한다.

**제주 풍력은 2024-06부터 사용하지 않는다**
- 2017~2023년 월평균은 약 28~90 MWh인데, 2024-06 7.5, 2025-03~12는 0.8~3.7 MWh로 급락한다. 6월 평균은 2019~2022년 29~55, 2024년 7.5, 2025년 1.7이다.
- 공공데이터포털 Open API(odcloud, 신청·호출 확인)로 2024·2025년 제주 풍력을 받아 파일과 비교한 결과 **행 단위로 완전히 일치**한다(불일치 0행). 따라서 파일 변환 문제가 아니라 KPX 원본 값의 변화다. **원인은 확인하지 못했다**(집계 범위 변경 추정, 근거 없음). KPX 문의가 필요하다.
- 제주 풍력 정답은 **2017-01-01 ~ 2024-05-31**(약 64,800시간)만 쓴다. 태양광은 2013~2025 전 기간이 정상이다.
- 출력 CSV의 `wind_usable` 열이 이 기준(`WIND_USABLE_END`)을 표시한다.

**학습 시 주의**
- 태양광 설비가 계속 늘어(2013~2017 평균 7.9 → 2025 53 MWh) 연도 또는 설비 용량 보정이 필요하다.
- 출력제한 시간대를 구분할 수 없어 억제된 값이 정답에 섞일 수 있다.
- KPX 값은 시장 참여분이고 ESS가 섞여 있어 "시장 거래된 발전량"이다.

**Open API (odcloud)**: 파일과 같은 10개 데이터셋을 제공하며 파일마다 주소가 다르다. 명세 `https://infuser.odcloud.kr/oas/docs?namespace=15065269/v1`, 호출은 `https://api.odcloud.kr/api/15065269/v1/uddi:<id>`에 `serviceKey`(query), `page`, `perPage`, `returnType`을 보낸다(2025 파일 id `76850689-e74c-402e-bfec-9142976b96c8`, 2024 파일 id `57e66d86-ea1d-4efb-9eb3-a6d575336841`). 명세에는 없지만 `cond[지역::EQ]`, `cond[연료원::EQ]`, `cond[거래일::EQ]` 필터가 동작했다(명세 외 동작이라 변경될 수 있음). 키는 `backend/.env`의 `KPX_GEN_API_KEY`.

## 권장 순서

1. **ASOS 시간자료 활용신청** (data.go.kr, 즉시 가능) — 신청 후 제주 지점번호 확인
2. **KPX 지역별 시간별 풍력·태양광 CSV 다운로드** (로그인 없이 가능할 수 있음) — 제공 기간과 제주 태양광 포함 여부 확인
3. 위 두 개로 학습 CSV 생성: 같은 기간에 정시 단위로 맞추고, 시간대를 KST로 통일
4. 수요 데이터 대안 결정 (팀 논의 필요)
5. 출력제어·충전소·설비 용량 보강 조사
