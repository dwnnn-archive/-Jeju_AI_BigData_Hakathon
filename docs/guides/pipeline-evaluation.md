# 파이프라인 end-to-end 점검 (과거 날짜 vs 실제 출력제한일)

발전량 모델, 수요 모델, 위험 규칙을 이어서 과거 날짜마다 돌려 보고, 판정이 **실제 출력제한일**과 맞는지 확인한 결과다. 규칙의 근거는 [demand-options.md](demand-options.md), 모델은 [jeju-model.md](jeju-model.md)·[demand-model.md](demand-model.md).

## 방법

| 항목 | 내용 |
|---|---|
| 기간 | 2023-01-01 ~ 2024-05-30 (494일, 날씨가 비는 22일은 제외) |
| 정답 | KPX 출력제어 이력에서 하루라도 풍력 또는 태양광 제어가 있으면 "출력제한일" (167일, 33.8%) |
| 실행 | 서비스가 쓰는 `ToolBundle`의 발전량·수요 경로와 `rules.evaluate`를 그대로 호출 |
| 모델 | **점검 기간을 학습에서 완전히 뺀** 별도 모델(풍력·태양광·수요 모두 2023-01 이전 데이터만 학습) |
| 날씨 | 과거 예보 이력이 없어 **그날의 실측**(ASOS 고산 풍속·기온·전운량, 제주 기온)을 예보 자리에 넣음 |

```bash
cd backend
python -m scripts.evaluate_pipeline <KPX_발전량_폴더> <KPX_수요_폴더> runtime/asos <출력제어_zip_또는_폴더> \
    --start 2023-01-01 --end 2024-05-30 --work-dir runtime/e2e
```

약 30초. 모델과 결과(`report.json`, 날짜별 `days.json`)가 `runtime/e2e`에 생긴다(Git에 올라가지 않음).

**피크 시간**: 적중한 135일 중 예측 피크 시간이 실제 제어 시간과 ±1시간 이내 **97.0%**, ±2시간 이내 99.3%.

**크기** (풍력 제어일 162일): 예측 피크 잉여 평균 55 MWh, 실제 하루 최대 시간당 제어량 평균 55 MWh. 날마다의 상관은 0.64(하루 최대), 0.65(하루 합)로 크기 순서는 대체로 맞지만 개별 날짜의 크기는 정확하지 않다.

**배분**: 위험으로 판정한 176일 중 98.9%에서 잉여가 배분 설비 용량(170 MWh) 이내다. *(이 통계는 평가 당시 설비 합계 170 MWh 기준이다. 이후 BESS 용량을 70에서 37.7 MWh로 낮춰 합계가 137.7 MWh(+ EV 실측분)가 되었으므로 같은 기준으로 재계산해야 한다. 원본 데이터 폴더가 필요해 아직 다시 돌리지 않았다.)*

## 예보 오차를 가정하면 (실측 대신 예보를 쓸 때)

위 결과는 실측 기상을 썼다. 서비스는 하루 전 계획이라 내일 날씨를 모르므로 예보를 쓴다. 실제 예보 오차는 측정하지 못해서(예보 이력이 없다) **오차를 가정해 섞어** 같은 점검을 다시 했다(오차 설정마다 3회 시드 평균, 같은 모델과 같은 규칙).

| 가정한 예보 오차 | CAUTION 이상 포착 | 정밀도 | 판정한 날 | CRITICAL 포착 | 정밀도 |
|---|---|---|---|---|---|
| 없음 (실측, 위 결과) | 80.8% | **76.7%** | 176일 | 61.1% | **82.3%** |
| 약: 풍속 하루 ±1.0 + 매시 ±1.0 m/s, 기온 ±1.5℃, 하늘상태 15% 틀림 | 82.2% | 62.7% | 219일 | 62.3% | 70.9% |
| 중: 풍속 하루 ±2.0 + 매시 ±1.5 m/s, 기온 ±2.5℃, 하늘상태 30% 틀림 | 80.8% | 55.1% | 245일 | 60.9% | 61.5% |
| 강: 풍속 하루 ±3.0 + 매시 ±2.0 m/s, 기온 ±3.5℃, 하늘상태 45% 틀림 | 76.6% | 49.2% | 260일 | 57.7% | 53.2% |

- **포착(재현율)은 거의 유지되고 정밀도가 크게 떨어진다.** 예보가 흔들리면 하루 중 최대 비율이 우연히 높게 나오는 날이 늘어 위험 판정이 176일에서 219~260일로 늘고, 늘어난 만큼이 오경보다.
- 임계값(0.40 / 0.45)은 실측 기상으로 맞춘 값이라 예보에서는 낮게 잡힌 셈이다. **예보 이력이 쌓이면 예보 기준으로 임계값을 다시 맞춰야 한다**(그러면 정밀도를 일부 되찾을 수 있다).
- 오차 크기는 가정이다. 기상청 단기예보의 실제 제주 오차는 확인하지 못했다.

## 당일 점검(초단기예보) 정책 시뮬레이션

**구상**: 기본은 하루 전 계획(단기예보)이다. 하루 전에 위험이면 거기서 끝내고(담당자 승인으로), **정상으로 나온 날만** 당일에 초단기예보로 두 번(07:45, 10:45) 다시 본다. 기상청 초단기예보는 이후 6시간을 예보하므로 각 점검은 지난 시간은 실측, 앞 6시간은 초단기예보, 그 뒤는 하루 전 예보로 판정한다. 점검 두 번 모두 정상이면 그날은 출력제한이 없는 것으로 본다.

초단기예보 이력이 없어 **오차를 가정**한 시뮬레이션이다. 하루 전 예보 오차는 "중"(풍속 하루 ±2.0 + 매시 ±1.5 m/s, 기온 ±2.5℃, 하늘상태 30% 틀림)으로 고정하고, 초단기예보 오차는 그 0.5배·0.25배·0.1배로 가정했다(3회 시드 평균, 494일, 실제 제한일 167일).

| 초단기예보 오차 | 하루 전만: 포착 / 정밀 / 판정일 | 하루 전 + 당일 2회: 포착 / 정밀 / 판정일 | 오경보 변화 |
|---|---|---|---|
| 하루 전의 0.5배 | 80.8% / 57.7% / 234일 | **93.4%** / 53.1% / 294일 | 99일 → 138일 |
| 0.25배 | 82.8% / 54.7% / 253일 | **92.8%** / 54.4% / 285일 | 115일 → 130일 |
| 0.1배 | 83.4% / 57.5% / 242일 | **93.4%** / 57.1% / 273일 | 103일 → 117일 |

- **놓침이 크게 준다**: 포착 81~83% → 약 93%(놓친 제한일 약 19% → 7%). 정밀도는 거의 그대로(53~57%)다. 늘어난 판정일 31~60일 중 17~21일이 새로 잡은 실제 제한일이고 나머지는 오경보다(새로 위험이 된 날의 적중 35~54%).
- **하루 전 단계의 오경보(99~130일)는 줄지 않는다.** 위험으로 판정한 날은 당일 재확인 없이 끝내기 때문이다. 당일 점검으로 위험 판정을 취소하거나 낮추는 방식을 추가하면 줄일 수 있으나 취소 절차(승인 철회)가 필요하다.
- 구조의 이득을 확인한 것이지 숫자가 보장되는 것은 아니다. **실제 초단기예보의 정확도와 하루 전 대비 오차 비율은 모른다**(기상청은 최신 예보만 주고 이력은 주지 않는다).
- 점검은 피크 시간(출력제한은 9~15시, 11~13시에 가장 많다) 3~6시간 전에 있다. 그 시간에 담당자 승인과 설비 대응이 가능한지는 확인하지 못했다.
- 초단기예보는 매시 30분에 생성되어 45분 이후 제공된다(활용가이드). 07:45 점검은 8~13시, 10:45 점검은 11~16시를 덮는다.

## 놓친 날과 오경보

- **놓친 32일은 작은 사건이다.** 풍력 제어량이 하루 합 중앙값 35 MWh로, 적중한 날(123 MWh)의 약 3분의 1이고 제어 시간도 3시간(적중 5시간)이다. 19일은 예측 비율이 0.35 이상으로 경계선(0.40) 바로 아래였다. 2일은 태양광 제어만 있던 날이다.
- **오경보 41일**은 예측 비율 중앙값 0.46으로 대부분 경계선을 넘었지만 실제 제어는 없었다. 11월에 13일이 몰려 있다(그 달 실제 제한일은 4일). 이유는 확인하지 못했다. 계통 상황(연계선, 최소 발전 조건)이나 수요 예측 오차일 수 있다.
- 월별로는 3~5월이 제한일 104일 중 90일을 포착했고, 오경보는 11월(13일)·4월(6일)·3월(5일) 순이다.

## 한계 (중요)

- **실측 기상을 썼다.** 서비스는 단기예보를 쓰므로 실제 성능은 이보다 낮다(위 표: 예보 오차를 가정하면 정밀도 77% → 49~63%). 과거 예보 이력이 없어 실제 오차는 측정하지 못했다. **서비스에서 예보를 저장하기 시작하면 실제 예보로 다시 평가하고 임계값을 다시 맞출 수 있다.**
- 기간이 17개월뿐이고 출력제한 이력이 2024-05-30(풍력)·2024-06-03(태양광)에서 끝나서 **2024-06 이후는 점검할 수 없다.** 입찰제 이후 제주 상황은 확인되지 않았다.
- 정답 "출력제한일"은 풍력 또는 태양광 제어가 하루 한 시간이라도 있으면 해당한다. 규모가 작은 날도 포함된다.
- 이 점검은 **모델과 규칙**을 이은 것이다. LangGraph 흐름, 승인 화면, 알림 같은 연결은 단위·통합 테스트가 따로 확인하며 이 점검에 포함되지 않는다.
- 승인과 실제 발송 차단(`validated: False`)은 그대로다.
