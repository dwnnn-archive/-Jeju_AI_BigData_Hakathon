# 제주 전체 단위 발전량 모델

KPX가 공개한 **제주 전체** 시간별 거래 발전량을 정답으로, 풍력 모델과 태양광 모델을 따로 학습한다. 설비별 계산이 아니다. 데이터 출처와 검증은 [data-acquisition.md](data-acquisition.md) 참고.

## 구조

| 모델 | 입력 | 정답 | 학습 / 검증 기간 |
|---|---|---|---|
| 풍력 | 시각, 월, 풍속, 기온 | KPX 제주 풍력 **+ 출력제어량**(잠재 발전량) MWh | 2017-01 ~ 2022-12 / 2023-01 ~ 2024-05 |
| 태양광 | 시각, 연중 일, 하늘상태, 기온, 연도 추세 | KPX 제주 태양광 MWh(출력제어 시간 제외) | 2018-08 ~ 2024-12 / 2025년 |

- 기상은 **고산(ASOS 185) 한 지점**이다. 4개 지점 평균 풍속과 상관이 같아(0.770 대 0.766) 한 지점이면 충분하다. 서비스에서는 같은 지점의 예보 격자(한경면 46,35)를 쓴다.
- 태양광 입력에 실측 일사량을 쓰지 않는다. 서비스에는 예보의 하늘상태(SKY)만 있어서, 학습에는 ASOS 전운량을 같은 3단계(맑음 1 / 구름많음 3 / 흐림 4)로 바꿔 쓴다. 전운량은 2019년부터 99% 이상 있고 2018-08 이전에는 거의 없다. 빈 시간은 직전 관측을 최대 3시간 이어 쓴다.
- 풍력 정답은 2017-01 ~ 2024-05만 쓴다(2024-06 이후 KPX 집계 급락).
- **출력제어 보정**: 풍력 정답은 `KPX 값 + 시간별 출력제어량`(제한이 없었다면의 발전량)이다. 잉여전력은 제한 전 발전량에서 나오기 때문이다. 제어량은 "차단 시점 발전량을 차단 시간으로 환산한 참고값"이다. 태양광은 제어량이 없어 제어된 시간(521시간)을 학습·검증에서 뺀다. `--wind-label observed`로 보정 없이 학습할 수도 있다.
- 학습과 추론이 같은 특징 생성 함수(`app/tools/jeju_model.py`)를 써서 입력이 어긋나지 않는다. 연도 추세는 학습 최댓값으로 고정한다.

## 실행

```bash
cd backend
# 1) 수집: KPX 원본 CSV는 data.go.kr에서 받아 한 폴더에 두고, ASOS는 .env의 ASOS_API_KEY로 수집
python -m scripts.collect_asos 2017-01 2025-12 runtime/asos
# 2) 학습용 CSV
python -m scripts.build_training_csv <KPX_CSV_폴더> runtime/asos runtime/train/jeju_train.csv \n    --curtailment <출력제어_zip_또는_폴더>
# 3) 학습 (xgboost 필요: uv sync --extra ml)
python -m scripts.train_jeju_model runtime/train/jeju_train.csv runtime/models/jeju
# 4) 서비스에서 사용: backend/.env 에 설정 (live 모드, KMA_API_KEY 필요)
#    JEJU_MODEL_DIR=runtime/models/jeju
```

`runtime/`은 Git에 올라가지 않는다. 모델 파일(`wind.json`, `solar.json`, `meta.json`)도 저장소에 없으므로 각자 3)으로 만든다(약 6초). `meta.json`에 검증 지표가 들어 있다.

`JEJU_MODEL_DIR`을 설정하면 live 발전량 예측이 이 모델을 쓴다. 모델 폴더 오류나 KMA 키 누락 시 조용히 다른 값으로 대체하지 않고 명시적으로 실패한다(`ALLOW_MOCK_FALLBACK`을 켠 경우에만 시연값으로 대체). 결과는 계속 `validated: False`라서 **승인과 실제 발송은 차단된다.**

## 검증 결과 (2026-11-16, 시간순 홀드아웃, 실측 기상 기준)

| | MAE | RMSE | R² | 하루 최대값 MAE | 기후값 기준선 MAE / R² |
|---|---|---|---|---|---|
| 풍력 (잠재 발전량 기준) | 27.0 MWh (정답 평균 64.8) | 36.5 | 0.67 | 31.8 | 50.1 / 0.06 |
| 태양광 | 15.9 MWh (정답 평균 53.2) | 26.2 | 0.89 | 37.8 | 23.6 / 0.69 |

기후값 기준선은 월×시각 평균이다. 두 모델 모두 기준선보다 크게 낫다. 풍력은 풍속이 기여도의 85%, 태양광은 시각 57%와 하늘상태 29%를 차지한다.

**출력제어 시간 검증** (검증 구간 제어 767시간 / 학습 구간 783시간)
- 같은 풍속대(±1 m/s, 같은 달)의 비제어 시간 KPX 풍력은 86.7인데 제어 시간의 KPX 값은 49.0이다. 제어량(평균 45.6)을 더하면 94.7로 비제어 수준(±9%)이 된다. 학습 구간에서도 같은 결과(97.2 대 58.1, 보정 후 106.1)다.
- 잠재 발전량 정답으로 학습하면 제어 시간의 MAE가 32.1에서 30.2로 줄고, 제어되지 않은 시간은 26.8로 그대로다. 제어 시간이 전체의 2.4%라 전체 지표 변화는 작다.

## 한계

- **하루 최대값 오차가 풍력 32, 태양광 40 MWh다.** 위험등급 경계(150 / 200 MWh, 재검증 구간 190~200)와 비교하면 CAUTION과 CRITICAL을 안정적으로 가르기 어렵다.
- **검증은 실측 기상이다.** 서비스는 단기예보를 쓰므로 실제 성능은 더 낮을 수 있다. 과거 예보 이력이 없어 이 차이를 측정하지 못했다.
- **출력제어량은 시간별 참고값이고 제어가 있던 날만 있으며 2024-05-30에서 끝난다.** 보정 후에도 억제량은 근사치다. 이력에 없는 이유로 낮은 값은 보정되지 않는다(예: 2024-02-10은 풍속 약 10 m/s에서 KPX 풍력이 13~60 MWh로 낮았지만 제어 기록이 없다. 원인은 확인하지 못했다. 단일 지점 풍속의 대표성 한계일 수 있다).
- KPX 값은 시장 참여 발전기 기준이고 ESS가 섞여 있어 "시장 거래된 발전량"이다.
- 태양광은 하늘상태를 3단계로만 써서 맑은 날 정오 피크를 낮게 예측하는 경향이 있다(2025-05-20 실제 236, 예측 142).
- 2024-06 이후 풍력은 KPX 값이 달라져 이 풍력 모델이 맞지 않는다. KPX 문의 결과에 따라 달라질 수 있다.
- 제주 수요 데이터는 아직 없어, 잉여전력 계산의 수요는 시연값이다.
