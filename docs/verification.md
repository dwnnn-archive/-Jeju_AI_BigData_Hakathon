# 구현 및 검증 기록

## 작업 순서

1. PDF 9쪽을 읽고 MW/MWh 혼용, 150/200 경계 중복, 시연 용량 170MWh와 90% 목표의 차이를 정리했다.
2. 폴더·에이전트 구조를 사용자에게 먼저 제시했다.
3. `dfea221`에서 README 구조를 `dwnnn`에 먼저 푸시하고 원격 SHA를 확인했다.
4. 도메인, 도구, 영속 에이전트 및 API, 학습/실행 문서를 구현했다.

## 검증

- `uv sync --frozen --extra dev --extra ml`: 고정 의존성 설치 확인.
- `pytest -q`: 48개 테스트 통과. 순수 계산, 시간 검증, 도구, 시연, 승인/반려, 재시작, 장애 재생, 인증, XGBoost 학습/로드 포함.
- `ruff check .`, `ruff format --check .`, `git diff --check`: 통과.
- 실제 uvicorn HTTP 서버: health/OpenAPI 200, boundary 분석 201, 재조회 후 230MWh, 미인증 승인 401, 인증 승인 후 mock_sent 확인. 검증용 서버는 종료했다.
- 독립 리뷰: 별도 OS 프로세스의 동시 승인도 감사 기록/발송함 1개, 시도 1회. 재조회 한도 0/1/3에서 각각 종료.

## 리뷰 수정

1. **승인 재생 충돌**: 그래프 resume 저장 후 감사 기록 전 장애를 재현하면 기존 승인에 반대되는 재시도가 200으로 통과했다. decision_intents를 먼저 커밋하도록 수정했다. 재현 테스트 실패 → 수정 후 409 및 원래 결정 재개 성공.
2. **비ASCII 인증 헤더**: 비교 함수에서 500이 발생하는 입력을 재현했다. UTF-8 바이트 비교로 수정해 401로 반환한다.
3. **학습 시간대 정렬**: +05:30 정시 자료가 KST에서는 30분 구간이 되는 것을 확인했다. KST 변환 후 정시 여부를 검증한다.

세 수정 모두 회귀 테스트의 실패를 확인한 뒤 구현했고 최종 전체 테스트를 통과했다. 미해결 리뷰 지적은 없다.

## 구현 선택 및 한계

- 사용자 요청의 단계와 브랜치를 그대로 사용했으며 추가 승인 라운드 없이 구현했다.
- 단일 호스트 SQLite/file lock을 선택했다. 처리량이 커지면 작업 큐와 공유 DB로 전환해야 한다.
- 제한형 자연어 파서/계산 결과 응답을 선택했다. 범용 LLM 대화는 제공하지 않는다.
- 배분은 피크 한 시간에만 적용한다. 일일 SOC 추적을 포함하는 운영 스케줄은 별도 구현이 필요하다.
- 실측 학습 자료, 확정 설비 용량, KPX 원천 API 명세, 실제 SOC 및 알림 계정이 제공되지 않았다. 시연 데이터·물리식 추정·mock 발송으로 실행한다.
- 기상청 응답 파싱은 고정 응답으로 검증했으며 실제 키를 통한 외부 통합, 모델 현장 정확도, 실전송은 검증하지 않았다. 운영 성능/안전성 인증을 의미하지 않는다.
