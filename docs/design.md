# 백엔드 설계

요구사항 및 그래프는 루트 README를 기준으로 한다. 사용자가 구조 공개 → README 푸시 → 구현을 순서대로 요청했으므로 별도의 승인 라운드를 추가하지 않고 구현한다.

## 선택

단일 FastAPI 프로세스와 모듈화된 LangGraph를 선택한다. 여러 마이크로서비스는 배포/복구 비용이 크고, 자유형 LLM 도구 선택은 수식 및 승인 제약을 보장하기 어렵다. 이 백엔드는 지정된 규칙으로 상태를 전이한다. SQLite 파일 잠금으로 동일 DB에 대한 변경을 직렬화한다. 고부하 환경에서는 PostgreSQL 체크포인트와 작업 큐로 전환할 수 있다.

## 입력과 출력

분석 요청은 날짜, 제주 거점(jeju/hallim/jocheon/haengwon), 모드(demo/live), 시연 시나리오(normal/critical/boundary), 선택적 질의를 받는다. 날짜/지역을 명시하거나 제한된 자연어에서 추출한다. 날짜는 KST 기준 오늘/내일 또는 ISO 날짜다. 모호한 입력은 거부한다.

24시간 기상과 수요를 같은 날짜/시간으로 검증한다. 기상청 격자 변환 및 API 파싱, KPX 정규화 JSON 입력 계약, 발전소 보정 JSON을 분리한다. KPX의 실제 API URL/응답 스키마가 제공되지 않았으므로 임의 API를 가정하지 않는다. 사용자가 계약에 맞는 중계 URL을 설정한다. 폴백은 명시된 시연 데이터이며 실데이터로 가장하지 않는다.

발전 예측 기본값은 물리 곡선 추정이며, XGBoost는 학습 데이터/모델 제공 시 선택한다. 학습 스크립트는 시간순 holdout MAE를 보고한다. 공공데이터 수집·실측 모델 정확도·실시간 SOC 검증은 데이터 확보 후 수행할 과제다.

## 상태와 안전

SQLite LangGraph 체크포인트에 요청, 시간별 결과, 출처, 재조회 횟수, 초안, 승인 결정을 보관한다. 승인 노드는 interrupt로 중단하며 동일 thread_id로 재개한다. API 생성 목록은 별도 runs 테이블로 관리한다. 승인 시 동일 분석 ID로 하나의 outbox 레코드를 생성한다. 승인자 ID는 토큰 설정에서 얻는다.

API_TOKEN이 없으면 로컬 조회/시연 분석은 가능하고, 승인/반려/발송에는 APPROVER_TOKEN이 반드시 필요하다. 기본 바인딩은 loopback이며 외부 배포 시 API_TOKEN, TLS, 접근제어가 필요하다. 범용 사용자 관리/역할 시스템은 범위 밖이다.

알림은 기본 mock이다. webhook 모드는 명시적 설정, HTTPS URL, 신뢰할 수 있는 데이터, 비추정 자원 가용량을 요구한다. 현 구현 자원은 모두 추정치이므로 실전송 게이트는 닫혀 있다. 실전송 통합 시 수신 시스템의 Idempotency-Key 보장이 필요하다. 전송 중 종료나 네트워크 오류는 delivery_unknown으로 취급하고 자동 재발송하지 않는다. 전력 설비의 제어 명령은 생성/전송하지 않는다.

## 완료 검증

230MWh→CRITICAL/170MWh 흡수/60MWh 잔여/390kg, 정상일 종료, 195→230 경계 재조회, 고정 경계 최대 재조회, 시간 누락/중복, cut-out, 용량 보정, 승인 인증/반려/중복, 프로세스 재생성 후 승인, 미승인 발송 차단을 검증한다.
